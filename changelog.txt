================================================================================
                        DHT Kernel Module — Changelog
================================================================================

Version 2.8  (21.09.2026)
────────────────────────────────────────────────────────────────────────────────

  Bug fixes and reliability improvements over v2.7.

  Critical
  ────────
  1. Use-after-free on unexport
     Added struct kref refcount to dht_sensor. In dht_proc_open, a sensor
     reference is acquired (kref_get_unless_zero). In dht_proc_release, the
     reference is released (kref_put). The sensor is freed only when the last
     file descriptor is closed. dht_sensor_release (kref callback) performs:
     stop_poll -> proc_remove -> mutex_destroy -> kfree.

  2. TOCTOU race during registration
     In dht_do_register, a duplicate check is performed again under list_lock
     immediately before list_add. If two threads passed the initial check
     simultaneously, the second one gets -EBUSY and frees the sensor via
     dht_sensor_put.

  3. Poll thread does not stop
     In dht_poll_thread_fn, the loop now breaks when effective_interval == -1
     (both global and per-sensor intervals disabled). Previously the thread
     could spin indefinitely if global auto_interval was set to -1 after
     the thread was started.

  Logic
  ─────
  4. DHT11 temperature below 5 C
     Temperature is now interpreted based on the sensor type determined from
     humidity: if h > 1000 (DHT11), c = data[2] * 10 is performed in the same
     branch. Removed the separate heuristic "if (c > 1250)" which skipped
     values 0-4 C for DHT11 sensors.

  5. Sensor type fluctuation
     In dht_do_measurement, the sensor type is now written only if
     sensor_type == SENSOR_TYPE_UNKNOWN. The first successful measurement
     locks the type permanently, preventing spurious type flips caused by
     borderline humidity readings.

  Reliability
  ───────────
  6. Preemption in timing-critical section
     Added preempt_disable() / preempt_enable() around the 40-bit bit-bang
     read loop in dht_read_sensor. Interrupts are NOT disabled — the DHT
     protocol's ~70 us pulses are wide enough that IRQ jitter is tolerable.

  7. gpiod_cansleep() check
     If the GPIO is behind a sleeping expander (e.g., I2C GPIO chip), reading
     now immediately returns ERR_GPIO_REQUEST with a diagnostic message in
     dmesg, instead of silently producing corrupted data.

  Code cleanup
  ────────────
  8. Dead code removed
     Removed LOG_BUF_LEN (was defined but never used) and info_text[INFO_BUF_LEN]
     field from struct dht_sensor (256 bytes per sensor, never used).
     INFO_BUF_LEN is retained — used as the local buffer size in sensor_info_read.

  9. kfree -> dht_sensor_put
     In the error path of dht_create_sensor_proc in dht_do_register, direct
     kfree is replaced with dht_sensor_put, since kref_init was already called
     before the error path.

  Intentionally not changed
  ─────────────────────────
  - gpiod_to_chip() / gpio_to_desc() are deprecated but replacing them with
    gpiod_get() via device tree requires a full rework of the registration
    model. Left as-is with the understanding that migration will be needed in
    future kernels.
  - procfs permissions (0666 for debug/auto_interval) are a user/distribution
    choice, not a bug.


Version 2.7  (21.09.2026)
────────────────────────────────────────────────────────────────────────────────

  Configuration file support

  New feature: optional configuration file /etc/default/dht, read at module
  load time. If the file is missing, the driver loads with defaults.

  Format:
    - Lines starting with '#' and empty lines are ignored
    - Unknown options produce warnings in dmesg
    - Invalid values produce warnings in dmesg

  Global options:
    DEBUG              Enable debug logging at load (= DEBUG=1)
    DEBUG=0|1          Explicitly disable/enable debug logging
    AUTO_INTERVAL=n    Global auto-poll interval in seconds (2-60)

  Sensor registration:
    SENSOR=<pin>       Register a sensor on the given BCM pin (no auto-poll)
    SENSOR=<pin>,<n>   Register with per-sensor auto-poll interval (2-60 sec)

  Implementation:
    - dht_do_register(pin, interval) extracted from export_write
    - dht_parse_config_line() parses one line at a time
    - dht_load_config() reads /etc/default/dht via VFS (filp_open + kernel_read)
    - Buffer allocated via kmalloc (no stack overflow)
    - Called at the end of dht_driver_init after procfs is set up

  Options are processed top-to-bottom:
    - AUTO_INTERVAL before SENSOR: sensor gets global interval at registration
    - AUTO_INTERVAL after SENSOR: sensor registers first, then global polling
      starts for all existing sensors


Version 2.6  (20.09.2026)
────────────────────────────────────────────────────────────────────────────────

  Shared /proc/sensors, safe unload, rate limiting, GPIO chip detection

  - Shared /proc/sensors: driver creates /proc/sensors only if it does not
    exist; removes it on unload only if it created it and it is empty
  - Safe module unload with two-phase teardown and module reference counting
  - Rate limiting for all measurements (manual and auto-poll, min 2 s gap)
  - GPIO chip detection: three-stage lookup (cached base, direct, full scan)
    with chip label verification for Pi 3/4/5 compatibility
  - Nanosecond-precision pulse timing for reliable reads across all Pi models


Version 2.5  (18.09.2026)
────────────────────────────────────────────────────────────────────────────────

  Initial release

  - Dynamic sensor export/unexport via procfs (/proc/sensors/dht/)
  - Per-sensor proc entries: pin, interval, measure, status_code, status_text,
    value, info, timestamp
  - Background polling thread with configurable per-sensor interval
  - Global auto-poll mode with shared interval
  - Supports DHT11, DHT22, AM2302 sensors
  - Compatible with Raspberry Pi 3/4/5 (BCM2835, BCM2711, RP1 GPIO chips)


================================================================================
                        Compatibility
================================================================================

  Kernel:     5.10+ (tested up to 6.18)
  Arch:       ARM64 (aarch64)
  Hardware:   Raspberry Pi 3/4/5 (and Pi Zero 2 W)
  Sensors:    DHT11, DHT22, AM2302
  Backward:   Compatible with v2.5 and v2.6 procfs interface
