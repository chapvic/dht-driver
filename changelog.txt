================================================================================
DHT11/DHT22/AM2302 Kernel Driver - Changelog
================================================================================

================================================================================
v2.8.3 (21.09.2026)
================================================================================

Critical
  9. Use-after-free in dht_driver_exit - proc_remove(proc_dir) in Phase 1
     frees all gpio<pin>/ entries. Phase 2 calls dht_sensor_put -> 
     dht_sensor_release -> proc_remove(sensor->proc_dir) on already-freed
     proc_dir_entry. Fix: set sensor->proc_dir = NULL before dht_sensor_put.
     proc_remove(NULL) is a safe no-op in the kernel.

  10. DHT22 negative temperature: c = (data[2] << 8) | data[3] includes the
      sign bit in the magnitude. c = -c gives -(32768 + abs_temp) instead of
      -(abs_temp). Fix: c = -(c & 0x7FFF) masks the sign bit before negation.
      Example: -25.1 C was shown as -3301.9 C. DHT11 unaffected (data[2] 0-50).

Medium
  11. dht_read_sensor re-resolves GPIO descriptor via dht_find_desc(pin) on
      every measurement, despite sensor->gpiod already holding a valid,
      gpio_request-ed descriptor. Fix: pass sensor->gpiod as a parameter to
      dht_read_sensor. Eliminates redundant lookup and potential descriptor
      mismatch if GPIO subsystem state changes.

Low
  12. Debug log: negative temperature printed as T=-25.-1 instead of
      T=-25.1 (C's % preserves sign of dividend). Fix: branch on temp < 0
      and use (-temp)/10, (-temp)%10 for the fractional part. Matches the
      formatting already used in sensor_value_read.

================================================================================
v2.8.2 (21.09.2026)
================================================================================

High
  5. dht_start_poll/dht_stop_poll called without list_lock in
     sensor_interval_write - race condition with auto_interval_write and
     dht_do_register. Fix: wrap poll thread start/stop calls in list_lock.
     Eliminates leaked task_struct or use-after-free on kthread_stop.

  6. Manual measurement races with auto-poll on same GPIO - two simultaneous
     bit-bang operations corrupt data for both readers. Fix: add atomic_t
     measuring flag to dht_sensor. atomic_cmpxchg(&sensor->measuring, 0, 1)
     before GPIO read. Manual: returns ERR_READ_FAILED. Auto: silently skips.

Medium
  7. auto_interval_write silently disables on invalid input - values outside
     [2,60] (except -1) silently set global_auto_interval to -1 and return
     success. Fix: return -EINVAL for invalid values, matching
     sensor_interval_write behavior. Validation before acquiring list_lock.

  8. DHT11/DHT22 heuristic fails at low humidity - DHT11 with humidity <= 3%
     produces h <= 1000, misidentified as DHT22. Fix: add secondary check
     (data[1] == 0 && data[3] == 0 && data[0] <= 100 && data[2] <= 50) to
     classify as DHT11 when decimal bytes are zero and values in DHT11 range.

================================================================================
v2.8.1 (21.09.2026)
================================================================================

Critical
  4. Poll thread exits via break when both intervals are -1, leaving
     sensor->poll_thread as a dangling pointer. If auto-poll is re-enabled,
     dht_start_poll sees stale non-NULL and does not start a new thread.
     Fix: replace break with idle loop - thread sleeps 1 second and rechecks
     intervals. If auto_interval or sensor->interval is re-enabled, poll
     resumes. If kthread_should_stop(), thread exits. poll_thread stays
     valid throughout.

================================================================================
v2.8 (21.09.2026)
================================================================================

Critical
  1. Use-after-free at unexport - added struct kref refcount in dht_sensor.
     In dht_proc_open, kref_get_unless_zero is called. In dht_proc_release,
     kref_put is called. Sensor is freed only when the last descriptor is
     closed. dht_sensor_release (kref callback): stop_poll -> proc_remove ->
     mutex_destroy -> kfree.

  2. TOCTOU at registration - in dht_do_register, duplicate check is repeated
     under list_lock before list_add. If two threads pass the primary check,
     the second gets -EBUSY and frees the sensor via dht_sensor_put.

  3. Poll thread does not stop - in dht_poll_thread_fn, added break if
     effective_interval == -1 (both intervals disabled).

Logical
  4. DHT11 temperature below 5 C - temperature is interpreted by the type
     determined from humidity: if h > 1000 (DHT11), c = data[2] * 10 in the
     same branch. Removed the separate heuristic if (c > 1250) that skipped
     values 0-4 C.

  5. Sensor type heuristic changes on every measurement - in
     dht_do_measurement, type is written only if sensor_type ==
     SENSOR_TYPE_UNKNOWN. First successful measurement locks the type.

Reliability
  6. Preemption in timing-critical section - added preempt_disable() /
     preempt_enable() around the 40-bit read cycle. IRQs are not disabled
     (IRQ jitter tolerable for ~70 us DHT pulses).

  7. gpiod_cansleep() check - if GPIO is behind a sleeping expander (I2C),
     read returns ERR_GPIO_REQUEST immediately with a diagnostic message
     instead of silent data corruption.

Code Cleanliness
  8. Dead code - removed LOG_BUF_LEN (unused) and info_text[INFO_BUF_LEN]
     (256 bytes per sensor, unused). INFO_BUF_LEN kept as the size of the
     local buffer in sensor_info_read.

  9. kfree -> dht_sensor_put - in the error path of dht_create_sensor_proc
     in dht_do_register, direct kfree is replaced with dht_sensor_put since
     kref_init was already called.

Not Changed (by design)
  gpiod_to_chip() / gpio_to_desc() - deprecated, but replacing with
  gpiod_get() via device tree requires a complete registration model
  rework. Left as-is with the understanding that future kernels will
  require migration.

  Permissions on debug/auto_interval (0666) - a user/distro choice, not a bug.

================================================================================
v2.7 (21.09.2026)
================================================================================

  - Configuration file support: optional /etc/default/dht for auto-registration
    at module load time. Lines starting with '#' and empty lines are ignored.
    Unknown options produce warnings in dmesg.
    Options: DEBUG, AUTO_INTERVAL, SENSOR=<pin>[,<interval>].

================================================================================
v2.6 (20.09.2026)
================================================================================

  - Shared /proc/sensors parent directory: coexists with other sensor drivers.
    /proc/sensors is created only if it does not exist; removed on exit only
    if we created it and it is now empty.
  - Safe module unload: two-phase cleanup (Phase 1: set exiting flag, disable
    auto-poll, remove procfs; Phase 2: stop threads, free memory). Module
    reference counting via try_module_get/module_put in proc open/release.
  - Rate limiting: MEAS_MIN_GAP (2 seconds) between all measurements (manual
    and auto-poll). Manual: returns ERR_TOO_SOON. Auto: silently skips.

================================================================================
v2.5 (18.09.2026)
================================================================================

  - Initial release.
  - Dynamic sensor export/unexport via procfs.
  - Per-sensor proc entries: pin, interval, measure, status_code, status_text,
    value, info, timestamp.
  - Background polling thread with configurable interval.
  - Global auto-poll mode with shared interval.
  - GPIO chip base caching for fast multi-sensor registration on Pi 3/4/5.
  - Nanosecond-precision pulse timing for reliable reads across all Pi models.
  - Error codes: ERR_SUCCESS, ERR_PIN_INVALID, ERR_GPIO_REQUEST,
    ERR_READ_FAILED, ERR_AUTO_MODE, ERR_TOO_SOON.

================================================================================
Compatibility
================================================================================

Kernel:     5.4+ (tested on 5.4, 5.10, 5.15, 6.1, 6.6)
Arch:       ARM64 (Raspberry Pi 3/4/5), ARM32 (Raspberry Pi 1/Zero/Zero W)
Backward:   v2.8.3 is fully backward-compatible with v2.8.2 configuration
            files and procfs interface. No user-facing changes.
