  NEW FEATURE: Configuration File Support
  =======================================

  The driver now reads an optional configuration file at module load time.
  This allows automatic sensor registration, debug mode activation, and
  global auto-poll configuration without manual procfs writes after
  insmod.

  File path: /etc/default/dht (optional — driver loads with defaults
  if the file is missing).

  Configuration file format:

    Lines starting with '#' and empty lines are ignored.
    Options are processed top-to-bottom in order of appearance.

    Global options:
      DEBUG                  Enable debug logging at load (same as DEBUG=1)
      DEBUG=0                Explicitly disable debug logging
      DEBUG=1                Explicitly enable debug logging
      AUTO_INTERVAL=N        Set global auto-poll interval in seconds (2-60)
                             Starts polling for all registered sensors
      AUTO_INTERVAL=-1       Disable global auto-poll

    Sensor registration:
      SENSOR=<pin>           Register a sensor on the given BCM pin number
                             (no auto-poll unless AUTO_INTERVAL is set)
      SENSOR=<pin>,<N>       Register with per-sensor auto-poll interval
                             N = 2-60 seconds

    Example file:

      # /etc/default/dht
      DEBUG=1
      AUTO_INTERVAL=10
      SENSOR=4               # DHT22 on GPIO4, uses global interval
      SENSOR=17,5            # DHT11 on GPIO17, polls every 5 seconds
      SENSOR=22              # Sensor on GPIO22, no auto-poll

  Error handling:
    - Missing config file         → driver loads normally (debug message only)
    - Unknown option name         → dmesg warning: "config: unknown option 'XXX'"
    - Invalid SENSOR pin          → dmesg warning: "config: SENSOR pin 'XX' invalid"
    - Invalid SENSOR interval     → dmesg warning: "config: SENSOR interval 'XX' invalid"
    - Invalid DEBUG value         → dmesg warning: "config: DEBUG='XX' invalid"
    - Invalid AUTO_INTERVAL value → dmesg warning: "config: AUTO_INTERVAL='XX' ..."

  Implementation details:
  ---------------------------------------------------------------------------

  1. dht_do_register(int pin, int interval) — NEW FUNCTION
     -------------------------------------------------------

     The full sensor registration logic (pin validation, duplicate check,
     GPIO resolution, kzalloc, procfs creation, initial measurement, list
     insertion, auto-poll start) has been extracted from export_write()
     into a standalone function.

     Parameters:
       pin      — BCM GPIO pin number (0-27)
       interval — auto-poll interval in seconds (2-60), or -1 to disable

     Returns: 0 on success, negative errno on failure.

     This extraction allows both export_write() and the config file
     parser to register sensors through the same code path, eliminating
     duplication.

  2. export_write() — SIMPLIFIED
     -----------------------------

     Now a thin wrapper: parses the BCM pin number from user-space input
     and calls dht_do_register(pin, -1). All registration logic lives in
     dht_do_register().

  3. dht_config_set_auto_interval(int val) — NEW FUNCTION
     -------------------------------------------------------

     Kernel-space counterpart of auto_interval_write(). Sets the global
     auto-poll interval from the config file. When a valid interval
     (2-60) is set, starts poll threads for all already-registered
     sensors that don't have one running yet.

  4. dht_parse_config_line(const char *line) — NEW FUNCTION
     -------------------------------------------------------

     Parses a single trimmed config line. Splits on '=' into key/value,
     then dispatches to the appropriate handler:

       DEBUG    → sets dht_debug via WRITE_ONCE
       AUTO_INTERVAL → calls dht_config_set_auto_interval()
       SENSOR   → parses "pin" or "pin,interval", calls dht_do_register()

     Invalid keys and values produce dmesg warnings via dht_err().

     Uses a local buffer of CONFIG_LINE_LEN (256 bytes) — not
     CONFIG_BUF_LEN (4096) — to avoid the -Wframe-larger-than warning.
     The function processes one line at a time from the kmalloc'd
     buffer in dht_load_config(), so 256 bytes is sufficient.

  5. dht_load_config() — NEW FUNCTION
     -------------------------------------------------------

     Opens /etc/default/dht via VFS (filp_open + kernel_read). Allocates
     a CONFIG_BUF_LEN (4096) byte buffer via kmalloc — NOT on the stack
     — to avoid exceeding the kernel's 2048-byte stack frame limit.

     Reads the entire file (up to 4095 bytes), null-terminates it, then
     splits into lines (handling both \n and \r\n). Each non-empty,
     non-comment line is passed to dht_parse_config_line().

     If the file does not exist (IS_ERR on filp_open), the function
     returns silently with a debug message. If kmalloc fails, logs an
     error and returns.

  6. dht_driver_init() — MODIFIED
     -------------------------------------------------------

     Added call to dht_load_config() at the END of the init function,
     after all procfs entries are created. This ensures that sensors
     registered from the config file get their per-sensor proc entries
     created correctly.

  7. New preprocessor constants
     -------------------------------------------------------

     CONFIG_PATH       "/etc/default/dht"   Path to the config file
     CONFIG_BUF_LEN    4096                 Max config file size (kmalloc)
     CONFIG_LINE_LEN   256                 Max single config line (stack)

  8. Header comment updated
     -------------------------------------------------------

     Added a "Configuration file" section to the file header comment,
     documenting all options, format, and an example, in the same style
     as the existing procfs interface documentation.


  Ordering semantics
  ==================

  Config options are processed top-to-bottom. This matters for
  AUTO_INTERVAL and SENSOR interaction:

  - If AUTO_INTERVAL=10 appears BEFORE SENSOR=4:
    The global interval is set first. When SENSOR=4 is registered,
    dht_do_register() detects the active global interval and starts
    the poll thread automatically.

  - If AUTO_INTERVAL=10 appears AFTER SENSOR=4:
    SENSOR=4 is registered first without auto-poll. Then AUTO_INTERVAL
    calls dht_config_set_auto_interval(), which iterates over all
    registered sensors and starts poll threads for those that don't
    have one yet.

  Both orderings produce the same end state: all registered sensors
  are polled at the global interval.

------------------------------------------------------------------------------
  v2.6                                                  (previous release)
------------------------------------------------------------------------------

  Shared /proc/sensors coexistence
  =================================
  - Ownership flag (we_created_parent) tracks whether the driver created
    /proc/sensors or reused an existing directory
  - remove_proc_subtree("sensors") removed — no longer destroys other
    drivers' entries
  - Smart init: creates /proc/sensors only if it doesn't exist; creates
    /proc/sensors/dht under existing parent if present
  - Smart exit: removes only /proc/sensors/dht; checks /proc/sensors
    emptiness via VFS iteration before removing the parent
  - dht_proc_dir_is_empty() uses filp_open + iterate_dir (struct
    proc_dir_entry is opaque in modern kernels)

  Safe module unloading
  =====================
  - try_module_get() in dht_proc_open() prevents rmmod while files are open
  - dht_exiting atomic flag blocks new opens during unload
  - Two-phase exit: remove procfs first, then stop threads and free memory

  Rate limiting
  =============
  - MEAS_MIN_GAP (2 seconds) applies to ALL measurements (manual + auto)
  - Manual measurements return ERR_TOO_SOON if too soon
  - Auto-poll measurements silently skip if too soon

  GPIO chip detection
  ====================
  - Three-stage lookup: cached base → direct → full scan
  - Supports Pi 5 (base offset 512+) via chip label matching
  - cached_chip_base set once, reused for all subsequent registrations


------------------------------------------------------------------------------
  v2.5                                                  (initial release)
------------------------------------------------------------------------------

  - Dynamic sensor export/unexport via procfs
  - Per-sensor proc entries: pin, interval, measure, status_code,
    status_text, value, info, timestamp
  - Global auto-poll mode with shared interval
  - Background polling thread per sensor
  - Nanosecond-precision pulse timing for DHT protocol
  - Support for DHT11, DHT22, and AM2302 sensors
  - Up to 32 simultaneously registered sensors
  - Compatible with kernel 5.15+ (proc_ops/pde_data abstraction)
