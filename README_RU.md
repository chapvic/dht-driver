# DHT11/DHT22/AM2302 — Драйвер датчика температуры и влажности

**Версия:** 2.8.3  
**Автор:** © 2026, Chapvic  
**Лицензия:** GPL v3  
**Ядро:** Linux 4.19+ (проверено на 5.4, 5.10, 5.15, 6.1, 6.6)  
**Платформа:** Raspberry Pi 1/2/3/4/5 (ARM и ARM64)

---

## Обзор

Модуль ядра Linux для чтения данных температуры и влажности с датчиков DHT11, DHT22 и AM2302, подключённых к GPIO-пинам Raspberry Pi. Драйвер создаёт procfs-интерфейс в `/proc/sensors/dht/` для управления регистрацией, настройкой и чтением данных.

### Ключевые возможности

- Динамическая регистрация сенсоров через procfs (export/unexport)
- Per-sensor proc-записи: температура, влажность, статус, конфигурация
- Фоновый поток опроса с настраиваемым интервалом
- Глобальный auto-poll режим с общим интервалом
- Кэширование базы GPIO-чипа для быстрой регистрации на Pi 3/4/5
- Наносекундная точность таймингов для надёжного чтения на всех моделях Pi
- Rate limiting для всех измерений (ручных и автоматических)
- Безопасная выгрузка модуля с подсчётом ссылок (module reference counting)
- Совместное использование `/proc/sensors` с другими драйверами
- Конфигурационный файл: опциональный `/etc/default/dht` для авто-регистрации при загрузке
- Учёт ссылок через kref — сенсор жив до закрытия всех procfs-файлов
- Защита от вытеснения (preempt_disable) во время bit-bang чтения
- Блокировка параллельных GPIO-чтений через atomic_t measuring flag

## Подключение

```
DHT11/DHT22/AM2302        Raspberry Pi GPIO
    VCC  ───────────────  3.3V (Pin 1 или 17)
    DATA ───────────────  BCM GPIO (4, 17, 22, ...)
    GND  ───────────────  GND (Pin 6, 9, 14, ...)
```

**Pull-up резистор:** 4.7 kОм–10 kОм между DATA и VCC (DHT11 часто имеет встроенный).

## Быстрый старт

### Ручная регистрация

```bash
# Сборка и загрузка
make
sudo insmod dht.ko

# Регистрация сенсора на BCM pin 4
echo 4 > /proc/sensors/dht/export

# Чтение значений
cat /proc/sensors/dht/gpio4/value
# Вывод: H=45.2
#        T=23.1

# Ручное измерение
echo 1 > /proc/sensors/dht/gpio4/measure

# Включение авто-опроса (каждые 10 секунд)
echo 10 > /proc/sensors/dht/gpio4/interval

# Выключение авто-опроса
echo -1 > /proc/sensors/dht/gpio4/interval

# Глобальный авто-опрос для всех сенсоров
echo 10 > /proc/sensors/dht/auto_interval

# Отключение глобального авто-опроса
echo -1 > /proc/sensors/dht/auto_interval

# Удаление сенсора
echo 4 > /proc/sensors/dht/unexport

# Выгрузка модуля
sudo rmmod dht
```

### Через конфигурационный файл

```bash
# /etc/default/dht
DEBUG=1
AUTO_INTERVAL=10
SENSOR=4
SENSOR=17,5
SENSOR=22
```

```bash
sudo insmod dht.ko
# Все сенсоры из конфига регистрируются автоматически
```

### Обработка ошибок

```bash
# Проверка статуса последнего измерения
cat /proc/sensors/dht/gpio4/status_code
# 0 = успех, 1 = неверный пин, 2 = ошибка GPIO,
# 3 = ошибка чтения, 4 = авто-режим активен, 5 = слишком скоро

cat /proc/sensors/dht/gpio4/status_text
# "OK" или описание ошибки
```

## Procfs интерфейс

### Глобальные записи

```
/proc/sensors/dht/
  debug         (rw) — отладочный лог: 0 = выкл (по умолчанию), 1 = вкл
  version       (r)  — версия драйвера
  export        (w)  — записать BCM-номер пина для регистрации сенсора
  unexport      (w)  — записать BCM-номер пина для удаления сенсора
  auto_interval (rw) — глобальный интервал авто-опроса (2–60, -1 = выкл)
```

### Per-sensor записи

```
/proc/sensors/dht/gpio<pin>/
  pin           (r)  — BCM GPIO-номер пина
  interval      (rw) — интервал авто-опроса в секундах (2–60, -1 = выкл)
  measure       (w)  — записать "1" для ручного измерения
                       (игнорируется, если interval != -1 или глобальный авто активен)
  status_code   (r)  — код ошибки (0 = успех)
  status_text   (r)  — описание ошибки
  value         (r)  — "H=<влажность>\nT=<температура>\n"
  info          (r)  — тип сенсора + время регистрации
  timestamp     (r)  — Unix-таймстамп последнего измерения
```

### Приоритет опроса

| Условие | Режим |
|---------|-------|
| `auto_interval` != -1 | Глобальный авто-опрос для всех сенсоров |
| `auto_interval` == -1, `interval` != -1 | Per-sensor авто-опрос |
| `auto_interval` == -1, `interval` == -1 | Ручной режим (echo 1 > measure) |

## Примеры

### Shell

```bash
# Регистрация и чтение
echo 4 > /proc/sensors/dht/export
cat /proc/sensors/dht/gpio4/value

# Авто-опрос каждые 5 секунд
echo 5 > /proc/sensors/dht/gpio4/interval

# Глобальный авто-опрос
echo 10 > /proc/sensors/dht/auto_interval

# Отладочный лог
echo 1 > /proc/sensors/dht/debug
dmesg | grep dht
```

### Python

```python
pin = 4

# Регистрация
with open('/proc/sensors/dht/export', 'w') as f:
    f.write(str(pin))

# Чтение значений
with open(f'/proc/sensors/dht/gpio{pin}/value') as f:
    data = f.read()
    # "H=45.2\nT=23.1\n"

# Ручное измерение
with open(f'/proc/sensors/dht/gpio{pin}/measure', 'w') as f:
    f.write('1')

# Статус
with open(f'/proc/sensors/dht/gpio{pin}/status_code') as f:
    code = int(f.read())
```

### Конфигурационный файл

```bash
# /etc/default/dht
DEBUG=1
AUTO_INTERVAL=10
SENSOR=4
SENSOR=17,5
SENSOR=22
```

### Безопасная выгрузка

```bash
# Отключить глобальный авто-опрос
echo -1 > /proc/sensors/dht/auto_interval

# Удалить все сенсоры
for pin in $(ls /proc/sensors/dht/ | grep gpio | sed 's/gpio//'); do
    echo $pin > /proc/sensors/dht/unexport
done

# Выгрузить модуль
sudo rmmod dht
```

## Коды ошибок

### Коды драйвера (status_code)

| Код | Константа | Описание |
|-----|-----------|----------|
| 0 | ERR_SUCCESS | Операция завершена успешно |
| 1 | ERR_PIN_INVALID | GPIO-пин вне допустимого диапазона |
| 2 | ERR_GPIO_REQUEST | Ошибка запроса/поиска GPIO-дескриптора |
| 3 | ERR_READ_FAILED | Ошибка чтения (контрольная сумма, таймаут) |
| 4 | ERR_AUTO_MODE | Ручное измерение при активном авто-опросе |
| 5 | ERR_TOO_SOON | Ручное измерение отклонено (rate limiting) |

### errno при export

| errno | Описание |
|-------|----------|
| -EINVAL | Неверный номер пина |
| -EBUSY | Пин уже зарегистрирован |
| -ENOMEM | Достигнут максимум сенсоров или ошибка выделения памяти |
| -ENODEV | GPIO не найден |
| -EIO | Ошибка измерения при регистрации |
| -EBUSY | GPIO занят другим драйвером |

## Архитектура

### Учёт ссылок (kref)

`struct dht_sensor` содержит `struct kref refcount`. При открытии procfs-файла `dht_proc_open` вызывает `kref_get`, при закрытии `dht_proc_release` — `kref_put`. Сенсор освобождается только когда последний файл закрыт, даже если пользователь уже вызвал `unexport`.

### Защита от вытеснения (preempt protection)

Во время bit-bang чтения (наносекундные тайминги) вызывается `preempt_disable()`. Это предотвращает вытеснение потока планировщиком во время критичного цикла чтения. После цикла вызывается `preempt_enable()`.

### Блокировка параллельных измерений (measuring flag)

Поле `atomic_t measuring` в `struct dht_sensor` предотвращает параллельные bit-bang чтения на одном GPIO. `atomic_cmpxchg` атомарно устанавливает флаг перед чтением. Ручные измерения получают `ERR_READ_FAILED` при конфликте, авто-опрос — молча пропускает.

### Определение типа сенсора

При первом успешном измерении тип сенсора (DHT11 или DHT22) определяется по формату данных:
- `h > 1000` — DHT11 (целые значения, byte 0 > 100 → 0x64*256 > 1000)
- `h <= 1000`, `data[1] == 0 && data[3] == 0`, `data[0] <= 100 && data[2] <= 50` — DHT11 с низкой влажностью
- Иначе — DHT22 (16-битные значения с десятыми долями)

Тип фиксируется после первого измерения (`if sensor_type == SENSOR_TYPE_UNKNOWN`) и не меняется.

### DHT22: отрицательная температура

DHT22 передаёт знак температуры в бите 7 `data[2]`. Температура вычисляется как `c = (data[2] << 8) | data[3]`. При отрицательной температуре бит знака (бит 15 комбинированного значения) маскируется: `c = -(c & 0x7FFF)`. Это даёт правильное значение, например `-251` для `-25.1 °C`.

### Передача GPIO-дескриптора

`dht_read_sensor` принимает `struct gpio_desc *desc` из `sensor->gpiod` вместо повторного вызова `dht_find_desc(pin)`. Устраняет избыточный поиск и потенциальную нестабильность при изменении GPIO-подсистемы между регистрацией и измерением.

### GPIO-чип: эксклюзивное владение

`dht_do_register` вызывает `gpio_request` для эксклюзивного занятия пина. Если пин уже занят другим драйвером, регистрация возвращает `-EBUSY`. Освобождение через `gpio_free` в `dht_sensor_release`.

### Rate limiting

`MEAS_MIN_GAP` (2 секунды) применяется ко всем измерениям. `last_attempt_time` обновляется перед чтением. Ручные измерения получают `ERR_TOO_SOON`, авто-опрос — молча пропускает.

### Безопасная выгрузка

Двухфазный cleanup в `dht_driver_exit`:
- Phase 1: `dht_exiting = 1` (блокировка новых open), `global_auto_interval = -1`, `proc_remove(proc_dir)` (удаление всех procfs, блокирует до закрытия файлов)
- Phase 2: splice списка, `sensor->proc_dir = NULL` (procfs уже удалён), `dht_sensor_put` для каждого сенсора

### Sleeping GPIO

`gpiod_cansleep(desc)` проверяет, находится ли GPIO за I2C/SPI-экспандером. Такие GPIO не работают с non-sleeping `gpiod_get_value` в tight loop. Драйвер возвращает `ERR_GPIO_REQUEST`.

### Загрузка конфигурации

`dht_load_config` читает `/etc/default/dht` при загрузке через VFS-чтение из kernel space. Буфер выделяется в куче (`kmalloc`), освобождается во всех путях. Строки парсятся, сенсоры регистрируются через `dht_do_register`.

## Известные ограничения

- **Deprecated GPIO API** — используется `gpio_to_desc` / `desc_to_gpio`. Миграция на `gpiod_get` через device tree требует мажорной версии.
- **GPIO за I2C-экспандерами** — sleeping GPIO отклоняются. Bit-bang требует non-sleeping доступа.
- **Дубликаты procfs при TOCTOU-гонке** — при одновременной регистрации одного пина временно создаются два каталога `gpio<pin>/`. Крайне маловероятно на практике.
- **Датчики вне диапазона** — DHT11 с влажностью < 20% или > 90% (вне спецификации) может ложно определиться. Эвристика в v2.8.2 покрывает большинство случаев.
- **Максимум 32 сенсора** — `MAX_SENSORS` задаётся в исходном коде.

## Устранение неполадок

| Симптом | Причина | Решение |
|---------|---------|---------|
| `status_code = 2`, "GPIO descriptor not found" | Пин не существует или GPIO-чип не обнаружен | Проверьте номер пина, загрузите модуль `gpiochip` |
| `status_code = 2`, "GPIO is on a sleeping chip" | GPIO за I2C/SPI-экспандером | Используйте прямой BCM GPIO, не экспандер |
| `status_code = 3`, "Read failed" | Плохой контакт, нет pull-up, датчик неисправен | Проверьте подключение, pull-up 4.7–10 kОм |
| `status_code = 4`, "Auto mode active" | Попытка ручного измерения при активном авто-опросе | Отключите auto_interval или per-sensor interval |
| `status_code = 5`, "Too soon" | Измерение раньше, чем через 2 секунды | Подождите 2 секунды между измерениями |
| `status_code = 3`, "Measurement already in progress" | Параллельное измерение на том же GPIO | Повторите позже, один читатель за раз |
| Отрицательная температура DHT22 показывает "-3301.9" | Бит знака не маскирован (исправлено в v2.8.3) | Обновите до v2.8.3 |
| Предупреждение компилятора о неиспользуемой переменной | Мёртвый код (исправлено в v2.8) | Обновите до v2.8+ |
| `echo 0 > auto_interval` возвращает успех | Молчаливое отключение (исправлено в v2.8.2) | Обновите до v2.8.2+ |
| Poll thread не перезапускается после отключения | `poll_thread` не очищался (исправлено в v2.8.1) | Обновите до v2.8.1+ |
| OOPS/KASAN при выгрузке с открытыми procfs | Use-after-free в exit (исправлено в v2.8.3) | Обновите до v2.8.3 |
