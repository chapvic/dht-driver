# Модуль ядра DHT11/DHT22/AM2302

Модуль ядра Linux для чтения данных о температуре и влажности с датчиков
DHT11, DHT22 и AM2302, подключённых к GPIO-пинам Raspberry Pi. Драйвер
создаёт интерфейс procfs в `/proc/sensors/dht/` для управления
регистрацией датчиков, конфигурацией и получением данных.

**Версия:** 2.8  
**Автор:** Chapvic  
**Лицензия:** GPL v3

## Обзор

Модуль ядра DHT предоставляет интерфейс на основе procfs для чтения
температуры и влажности с датчиков серии DHT, подключённых к GPIO-пинам
Raspberry Pi. Ключевые возможности:

- Динамический export/unexport датчиков через procfs
- Per-sensor записи procfs для температуры, влажности, статуса и конфигурации
- Фоновый поток опроса с настраиваемым интервалом
- Глобальный режим автоопроса с общим интервалом
- Кэширование базы GPIO-чипа для быстрой регистрации нескольких датчиков на Pi 3/4/5
- Наносекундная точность измерения импульсов для надёжного чтения на всех моделях Pi
- Rate limiting для всех измерений (ручные и автоопрос)
- Безопасная выгрузка модуля со счётчиком ссылок и управлением жизненным циклом через kref
- Защита от вытеснения в timing-critical секции чтения
- Shared `/proc/sensors`: сосуществует с другими драйверами датчиков
- Файл конфигурации: опциональный `/etc/default/dht` для авторегистрации при загрузке

## Поддерживаемое оборудование

### Датчики

| Датчик | Диапазон температур | Диапазон влажности | Точность | Формат данных |
|--------|---------------------|--------------------|---------|--------------|
| DHT11  | 0-50 °C            | 20-90%             | ±2 °C / ±5% | Целые числа |
| DHT22  | -40 до 80 °C       | 0-100%             | ±0,5 °C / ±2% | 16-бит, масштаб. x10 |
| AM2302 | -40 до 80 °C       | 0-100%             | ±0,5 °C / ±2% | 16-бит, масштаб. x10 |

AM2302 — проводная версия DHT22 с тем же протоколом.

### Модели Raspberry Pi

| Модель | GPIO-чип | Метка чипа | Базовое смещение |
|--------|----------|-----------|------------------|
| Pi 5        | RP1           | `pinctrl-rp1`   | 512+ |
| Pi 4        | BCM2711       | `pinctrl-bcm2711` | 0 |
| Pi 3/Zero 2 | BCM2835     | `pinctrl-bcm2835` | 0 |

### Совместимость ядра

- **Минимум:** 5.10
- **Тестировано:** до 6.18 (ядро Raspberry Pi OS `6.18.50+rpt-rpi-v8`)
- **Архитектура:** ARM64 (aarch64)

## Подключение

Подключите датчик к любому доступному BCM GPIO-пину:

```
Датчик DHT       Raspberry Pi
─────────        ────────────
VCC (пин 1)  ->  3.3V  (пин 1 или 17)
DATA (пин 2) ->  BCM GPIO-пин на ваш выбор
GND (пин 4)  ->  GND   (пин 6, 9, 14, 20, 25, ...)
```

**Подтягивающий резистор:** между DATA и VCC требуется резистор
4,7 кОм–10 кОм. Некоторые платы датчиков (например, AM2302) уже имеют
этот резистор на плате.

**Выбор пина:** можно использовать любой BCM-пин 0-27. Несколько датчиков
можно подключить к разным пинам одновременно (до 32 датчиков).

**Примечание:** GPIO-пины за I2C/SPI-экспандерами не поддерживаются —
драйвер проверяет `gpiod_cansleep()` и отклоняет такие пины с ошибкой.

## Быстрый старт

```bash
# 1. Установить заголовочные файлы ядра
sudo apt install linux-headers-$(uname -r)

# 2. Собрать модуль
make

# 3. Загрузить модуль
sudo insmod dht.ko

# 4. Зарегистрировать датчик на BCM-пине 4
echo 4 | sudo tee /proc/sensors/dht/export

# 5. Прочитать температуру и влажность
cat /proc/sensors/dht/gpio4/value

# 6. Включить автоопрос (каждые 10 секунд)
echo 10 | sudo tee /proc/sensors/dht/auto_interval

# 7. Прочитать последние кэшированные значения
cat /proc/sensors/dht/gpio4/value
cat /proc/sensors/dht/gpio4/timestamp

# 8. Отменить регистрацию датчика
echo 4 | sudo tee /proc/sensors/dht/unexport

# 9. Выгрузить модуль
sudo rmmod dht
```

## Файл конфигурации

Драйвер считывает опциональный файл конфигурации `/etc/default/dht` при
загрузке модуля. Если файл отсутствует, драйвер загружается со значениями
по умолчанию.

### Формат

- Строки, начинающиеся с `#`, и пустые строки игнорируются
- Неизвестные опции вызывают предупреждение в dmesg
- Недопустимые значения вызывают предупреждение в dmesg
- Опции чувствительны к регистру

### Опции

| Опция | Формат | Описание |
|-------|--------|----------|
| `DEBUG` | `DEBUG` или `DEBUG=0\|1` | Включить/выключить отладку при загрузке |
| `AUTO_INTERVAL` | `AUTO_INTERVAL=n` | Глобальный интервал автоопроса (2-60 секунд) |
| `SENSOR` | `SENSOR=<pin>` | Зарегистрировать датчик (без автоопроса) |
| `SENSOR` | `SENSOR=<pin>,<n>` | Зарегистрировать с per-sensor интервалом (2-60) |

### Пример

```bash
# /etc/default/dht
DEBUG=1
AUTO_INTERVAL=10
SENSOR=4              # DHT22 на GPIO4, использует глобальный интервал
SENSOR=17,5           # DHT11 на GPIO17, опрос каждые 5 секунд
SENSOR=22             # Датчик на GPIO22, без автоопроса
```

### Обработка ошибок

| Ситуация | Поведение |
|----------|----------|
| Файл отсутствует | Тихо, отладочное сообщение в dmesg |
| Неизвестная опция | `config: unknown option 'XXX'` в dmesg |
| Недопустимый пин | `config: SENSOR pin 'XX' invalid (0-27)` в dmesg |
| Недопустимый интервал | `config: SENSOR interval 'XX' invalid (2-60 or -1)` в dmesg |
| Недопустимое DEBUG | `config: DEBUG='XX' invalid (expected 0 or 1)` в dmesg |
| Недопустимый AUTO_INTERVAL | `config: AUTO_INTERVAL='XX' is not a valid integer` или `out of range` в dmesg |

### Порядок обработки

Опции обрабатываются сверху вниз. Это важно для взаимодействия
`AUTO_INTERVAL` и `SENSOR`:

- Если `AUTO_INTERVAL=10` стоит **до** `SENSOR=4`, датчик автоматически
  получает глобальный автоопрос при регистрации.
- Если `AUTO_INTERVAL=10` стоит **после** `SENSOR=4`, датчик сначала
  регистрируется без опроса, затем `AUTO_INTERVAL` запускает опрос для
  всех зарегистрированных датчиков.

## Интерфейс procfs

### Глобальные записи: `/proc/sensors/dht/`

```
/proc/sensors/dht/
  debug         (rw) - отладка: 0 = выкл. (по умолчанию), 1 = вкл.
  version       (r)  - версия драйвера
  export        (w)  - записать номер BCM-пина для регистрации датчика
  unexport      (w)  - записать номер BCM-пина для отмены регистрации
  auto_interval (rw) - глобальный интервал автоопроса (2-60, -1 = выкл.)
```

### Per-sensor записи: `/proc/sensors/dht/gpio<pin>/`

```
/proc/sensors/dht/gpio4/
  pin           (r)  - номер BCM GPIO-пина
  interval      (rw) - интервал автоопроса в секундах (2-60, -1 = выкл.)
  measure       (w)  - записать "1" для запуска измерения
  status_code   (r)  - код ошибки (0 = успех)
  status_text   (r)  - описание ошибки
  value         (r)  - "H=<влажность>\nT=<температура>\n"
  info          (r)  - тип датчика + время регистрации
  timestamp     (r)  - Unix-временная метка последнего измерения
```

### Приоритет опроса

| Приоритет | Источник | Условие |
|-----------|----------|---------|
| 1 (высший) | Глобальный `auto_interval` | Установлен 2-60 |
| 2 | Per-sensor `interval` | Установлен 2-60, глобальный = -1 |
| 3 (нет) | Ручной `measure` | Оба интервала = -1 |

## Примеры использования

### Ручной режим (без автоопроса)

```bash
echo 4 | sudo tee /proc/sensors/dht/export
echo 1 | sudo tee /proc/sensors/dht/gpio4/measure
cat /proc/sensors/dht/gpio4/value
# Вывод: H=45.2
#        T=23.1
```

### Per-sensor автоопрос

```bash
echo 4 | sudo tee /proc/sensors/dht/export
echo 5 | sudo tee /proc/sensors/dht/gpio4/interval
# Теперь датчик опрашивается каждые 5 секунд
cat /proc/sensors/dht/gpio4/value
cat /proc/sensors/dht/gpio4/timestamp
```

### Глобальный автоопрос

```bash
echo 4 | sudo tee /proc/sensors/dht/export
echo 17 | sudo tee /proc/sensors/dht/export
echo 10 | sudo tee /proc/sensors/dht/auto_interval
# Оба датчика опрашиваются каждые 10 секунд
```

### Shell-скрипт

```bash
#!/bin/bash
# Чтение всех зарегистрированных датчиков
for dir in /proc/sensors/dht/gpio*/; do
    pin=$(cat "${dir}pin")
    value=$(cat "${dir}value")
    echo "GPIO${pin}: ${value}"
done
```

### Python

```python
import time

def read_sensor(pin):
    with open(f"/proc/sensors/dht/gpio{pin}/value") as f:
        data = f.read()
    h, t = None, None
    for line in data.strip().split("\n"):
        if line.startswith("H="):
            h = float(line[2:])
        elif line.startswith("T="):
            t = float(line[2:])
    return h, t

# Регистрация и опрос
with open("/proc/sensors/dht/export", "w") as f:
    f.write("4")

with open("/proc/sensors/dht/gpio4/interval", "w") as f:
    f.write("5")

while True:
    h, t = read_sensor(4)
    print(f"Влажность: {h}%  Температура: {t}C")
    time.sleep(5)
```

### Файл конфигурации

```bash
sudo tee /etc/default/dht << 'EOF'
DEBUG=1
AUTO_INTERVAL=10
SENSOR=4
SENSOR=17,5
EOF

sudo rmmod dht && sudo insmod dht.ko
# Датчики автоматически регистрируются при загрузке
```

### Безопасная выгрузка

```bash
# Сначала отменить регистрацию датчиков (опционально — выгрузка модуля выполнит очистку)
echo 4  | sudo tee /proc/sensors/dht/unexport
echo 17 | sudo tee /proc/sensors/dht/unexport
sudo rmmod dht
```

## Коды ошибок

### Коды драйвера (в `status_code`)

| Код | Константа | Описание |
|-----|-----------|----------|
| 0 | `ERR_SUCCESS` | Операция выполнена успешно |
| 1 | `ERR_PIN_INVALID` | Номер GPIO-пина вне диапазона (0-27) |
| 2 | `ERR_GPIO_REQUEST` | Ошибка запроса/поиска GPIO, или GPIO на sleeping-чипе |
| 3 | `ERR_READ_FAILED` | Ошибка чтения данных (контрольная сумма, таймаут, все попытки) |
| 4 | `ERR_AUTO_MODE` | Ручное измерение при активном автоопросе |
| 5 | `ERR_TOO_SOON` | Rate limiting: менее 2 сек с последнего измерения |

### errno при export/unexport

| errno | Значение |
|-------|---------|
| `-EINVAL` | Недопустимый номер пина |
| `-EBUSY` | Пин уже зарегистрирован (или TOCTOU race) |
| `-ENOMEM` | Достигнут максимум датчиков или ошибка выделения памяти |
| `-ENODEV` | GPIO-дескриптор не найден |
| `-EIO` | Ошибка начального измерения |

## Архитектура

### Учёт ссылок (kref)

Каждый датчик защищён счётчиком ссылок `struct kref`. Это предотвращает
use-after-free при отмене регистрации датчика, когда файл procfs ещё открыт:

- `dht_proc_open` берёт ссылку (`kref_get_unless_zero`)
- `dht_proc_release` отпускает ссылку (`kref_put`)
- `dht_sensor_release` (callback kref) освобождает все ресурсы, когда
  последняя ссылка сброшена: остановка потока опроса, удаление procfs,
  уничтожение мьютекса, освобождение памяти
- `kref_init` вызывается после `kzalloc` в `dht_do_register`, начальное
  значение refcount = 1 (владелец — список датчиков)

### Защита от вытеснения

Цикл чтения 40 бит в `dht_read_sensor` обёрнут в `preempt_disable()` /
`preempt_enable()` для предотвращения искажения таймингов из-за
переключения контекста. Прерывания НЕ отключаются — импульсы DHT (~70 мкс)
достаточно широкие, и случайный IRQ jitter допустим.

### Определение типа датчика

Тип датчика (DHT11 или DHT22) определяется по формату данных влажности
при первом успешном измерении:

- Если объединённое 16-битное значение влажности > 1000: DHT11 (целочисленный формат)
- Иначе: DHT22/AM2302 (16-битный, масштабированный x10)

После определения тип фиксируется навсегда (`sensor_type` записывается
только при `SENSOR_TYPE_UNKNOWN`). Это предотвращает ложные смены типа
из-за пограничных значений.

### Определение GPIO-чипа

Драйвер использует трёхстадийный поиск для преобразования BCM-номеров пинов
в GPIO-дескрипторы:

1. **Быстрый путь:** если `cached_chip_base` известен, вычислить
   `global = base + bcm_pin` (обычный случай после первой регистрации)
2. **Прямой поиск:** `gpio_to_desc(bcm_pin)` — работает на Pi 3/4, где base = 0
3. **Полный скан:** перебор GPIO-номеров 0-2048 в поисках Pi GPIO-чипа,
   где локальное смещение совпадает с BCM-пином

При первом успехе база чипа кэшируется для последующих регистраций.

### Rate Limiting

Все измерения (ручные и автоопрос) ограничены минимальным интервалом
`MEAS_MIN_GAP` (2) секунды между попытками:

- Ручные измерения, нарушающие интервал, возвращают `ERR_TOO_SOON`
- Измерения автоопроса, нарушающие интервал, пропускаются молча
  (сохраняются последние кэшированные данные)

### Безопасная выгрузка модуля

Драйвер использует двухфазное отключение:

**Фаза 1 — блокировка нового доступа и удаление procfs:**
1. Установить флаг `dht_exiting` (новые вызовы `dht_proc_open` возвращают `-ENODEV`)
2. Отключить глобальный автоопрос (предотвращает запуск новых потоков)
3. Удалить все procfs-записи (`proc_remove` блокирует до закрытия открытых файлов)

**Фаза 2 — остановка потоков и освобождение памяти:**
4. Перенести список датчиков под блокировкой (новые датчики невозможны — procfs удалён)
5. Для каждого датчика: сбросить ссылку через `dht_sensor_put`

Счётчик ссылок модуля (увеличивается в `dht_proc_open`) предотвращает
выполнение `rmmod` до закрытия всех открытых файлов procfs.

### Детекция sleeping-чипа

`gpiod_cansleep()` проверяется перед каждым чтением. Если GPIO находится
за sleeping-экспандером (например, I2C GPIO-чип), чтение немедленно
возвращает `ERR_GPIO_REQUEST` с диагностическим сообщением вместо попытки
выполнения timing-critical цикла, который привёл бы к искажённым данным.

### Загрузка файла конфигурации

При загрузке модуля, после настройки procfs, `dht_load_config()` открывает
`/etc/default/dht` через слой VFS (`filp_open` + `kernel_read`). Буфер
выделяется через `kmalloc` (не на стеке), чтобы избежать предупреждений
о переполнении стека. Строки парсятся по одной функцией
`dht_parse_config_line()`.

## Известные ограничения

1. **Устаревший GPIO API:** используются `gpiod_to_chip()` / `gpio_to_desc()`,
   которые устарели. Миграция на `gpiod_get()` через device tree требует
   полной переработки модели регистрации.
2. **Нет I2C/SPI GPIO-экспандеров:** timing-critical цикл чтения требует
   non-sleeping доступа к GPIO. GPIO за I2C/SPI-экспандерами отклоняются.
3. **Минимум 2 сек между чтениями:** датчикам DHT нужно не менее 2 секунд
   между чтениями. Это обеспечивается rate limiting.
4. **Автоопределение типа датчика:** тип определяется при первом успешном
   измерении и фиксируется навсегда. Если подключён неправильный датчик
   изначально, тип будет неверным до отмены и повторной регистрации.
5. **Тайминги single-wire протокола:** чтение критично ко времени (~4 мс).
   Хотя вытеснение отключено во время чтения, IRQ jitter может периодически
   вызывать ошибки (обрабатывается повторными попытками).
6. **Максимум 32 датчика:** жёсткий лимит, заданный `MAX_SENSORS`.

## Устранение неполадок

| Проблема | Возможная причина | Решение |
|----------|------------------|---------|
| `GPIO descriptor not found` | Недопустимый пин или чип не найден | Проверьте номер пина (0-27); проверьте dmesg на наличие определения чипа |
| `Sensor data read failed` | Проводка, резистор или датчик | Проверьте проводку; убедитесь в наличии pull-up 4,7-10 кОм; попробуйте другой пин |
| `GPIO is on a sleeping chip` | GPIO за I2C/SPI-экспандером | Используйте нативные GPIO-пины Pi |
| `Too soon since last measurement` | Rate limiting (мин. 2 сек) | Подождите 2 секунды между ручными чтениями |
| `rmmod: Module dht is in use` | Файл procfs ещё открыт | Закройте все файлы в `/proc/sensors/dht/` |
| Температура 0 для DHT11 | Чтения DHT11 ниже 5 °C (исправлено в v2.8) | Обновитесь до v2.8 |
| Тип датчика постоянно меняется | Флуктуация типа (исправлено в v2.8) | Обновитесь до v2.8 |
| Предупреждение компилятора: frame size | Большой буфер на стеке (исправлено в v2.7) | Обновитесь до v2.7+ |

## Требования для сборки

- Заголовочные файлы ядра Linux (соответствующие работающему ядру)
- Кросс-компилятор GCC для ARM64 (или нативный компилятор на Raspberry Pi)
- Тестированные комбинации:
  - Raspberry Pi 5 + ядро 6.18.50+rpt-rpi-v8
  - Raspberry Pi 4 + ядро 6.1.x
  - Raspberry Pi 3 + ядро 5.15.x

Модуль обратно совместим с procfs-интерфейсом v2.5 и v2.6. Существующие
скрипты, читающие `/proc/sensors/dht/gpio*/value`, продолжат работать
без изменений.
