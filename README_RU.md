## Обзор

Драйвер DHT предоставляет интерфейс на основе procfs для чтения температуры и влажности с датчиков DHT11, DHT22 и AM2302, подключённых к выводам GPIO Raspberry Pi.

Ключевые возможности:

- Динамическая регистрация датчиков через procfs (`export`/`unexport`)
- Индивидуальные proc-записи для каждого датчика: температура, влажность, статус и конфигурация
- Фоновый поток опроса с настраиваемым интервалом (индивидуальным или глобальным)
- Ручной запуск измерения через procfs
- Наносекундная точность таймингов импульсов для надёжного чтения на всех моделях Pi
- Кэширование базы GPIO-чипа для быстрой регистрации нескольких датчиков на Pi 3/4/5
- Ограничение частоты измерений (для ручных и автоматических замеров)
- Безопасная выгрузка модуля со счётчиком ссылок (`kref`)
- Разделяемый каталог `/proc/sensors`: сосуществует с другими драйверами датчиков
- Файл конфигурации: опциональный `/etc/default/dht` для авторегистрации при загрузке
- Совместимость с ядрами: 5.0–6.18+ (с компиляционными API-шеймами)
- Поддержка DKMS: автоматическая пересборка при обновлении ядра

## Архитектура протокола DHT

Датчики DHT11/DHT22/AM2302 используют проприетарный однопроводной двунаправленный протокол. Хост (MCU) инициирует обмен, датчик отвечает 40 битами данных (5 байт).

### Последовательность обмена

1. **Старт-сигнал хоста**: MCU удерживает линию данных в низком уровне не менее 18 мс (драйвер использует 20 мс)
2. **Освобождение линии хостом**: MCU переключает линию на вход; подтягивающий резистор переводит её в высокий уровень
3. **Ответ датчика** (20–40 мкс после освобождения):
   - Низкий импульс ~80 мкс
   - Высокий импульс ~80 мкс
4. **Передача данных** (40 бит):
   - Каждый бит: ~50 мкс низкий импульс, затем высокий импульс, длительность которого кодирует значение
   - **Бит 0**: высокий импульс ~26 мкс
   - **Бит 1**: высокий импульс ~70 мкс
5. **Конец кадра**: линия возвращается в состояние высокого уровня

### Кодирование битов

| Значение бита | Низкий импульс | Высокий импульс |
|---------------|----------------|-----------------|
| 0             | ~50 мкс        | ~26 мкс         |
| 1             | ~50 мкс        | ~70 мкс         |

Драйвер использует порог **40 мкс** (`BIT_THRESHOLD = 40000 нс`) для различения 0 и 1.

### 40-битный кадр данных

| Байт | Поле               | Формат DHT11              | Формат DHT22              |
|------|--------------------|---------------------------|---------------------------|
| 0    | Влажность, целое   | 0–100 (целое)             | RH старший байт           |
| 1    | Влажность, дробное | 0 (всегда ноль)            | RH младший байт           |
| 2    | Температура, целое | 0–50 (целое)              | T старший байт (бит 7 = знак) |
| 3    | Температура, дробное| 0 (всегда ноль)           | T младший байт            |
| 4    | Контрольная сумма  | (byte0+byte1+byte2+byte3) & 0xFF | Аналогично           |

**DHT11** передаёт только целые значения (дробные байты всегда 0). Значения масштабируются x10 в драйвере для единообразия.

**DHT22/AM2302** передаёт 16-битные значения с масштабом x10: влажность как `(byte0 << 8) | byte1`, температура как `((byte2 & 0x7F) << 8) | byte3`. Бит 7 байта 2 — знаковый бит для отрицательных температур.

### Параметры таймингов

| Параметр                | Значение    | Описание                                   |
|-------------------------|-------------|--------------------------------------------|
| Старт-сигнал (низкий)   | 20 мс       | Хост удерживает линию в низком уровне       |
| Задержка ответа датчика | 20–40 мкс   | После освобождения линии хостом             |
| Низкий импульс бита     | ~50 мкс     | Фиксированный низкий уровень перед битом    |
| Высокий импульс (0)     | ~26 мкс     | Ниже `BIT_THRESHOLD` (40 мкс)               |
| Высокий импульс (1)     | ~70 мкс     | Выше `BIT_THRESHOLD` (40 мкс)               |
| Таймаут импульса        | 200 мкс     | `PULSE_TIMEOUT_NS` — отмена при превышении   |
| Общая длительность кадра| ~4 мс       | 40 бит + рукопожатие                         |
| Мин. интервал чтений    | 2 с         | `MEAS_MIN_GAP` — время восстановления датчика|

Драйвер отключает вытеснение (`preempt_disable`/`preempt_enable`) во время bit-bang чтения для предотвращения искажения таймингов из-за переключения контекста. Прерывания остаются включёнными, чтобы не влиять на задержки системы.

## Подключение

### GPIO-разъём Raspberry Pi

Подключите вывод данных датчика к любому доступному выводу GPIO (нумерация BCM). Драйвер принимает номера BCM 0–27.

```
Датчик DHT        Raspberry Pi
---------        ------------
VCC (пин 1)  -   3.3В (пин 1 или 17)
DATA         -   GPIO пин на выбор (например, GPIO4 = пин 7)
GND (пин 4)  -   GND (пин 6 или 9)
```

### Подтягивающий резистор

Большинство модулей DHT содержат встроенный подтягивающий резистор (4.7k–10k). При использовании отдельного датчика:

- Подключите резистор 4.7–10 кОм между DATA и VCC (3.3В)
- Без подтягивающего резистора показания будут нестабильными или невозможными

### Выбор пина

- Поддерживаются любые BCM GPIO пины 0–27
- Избегайте пинов со специальными функциями (GPIO14/15 = UART, GPIO3 = I2C SDA), если эти интерфейсы используются
- GPIO4 — частый выбор для DHT-датчиков на Raspberry Pi

## Быстрый старт

```bash
# 1. Склонируйте или скопируйте файлы драйвера в каталог
cd dht-driver

# 2. Соберите
make

# 3. Загрузите модуль
sudo insmod dht.ko

# 4. Зарегистрируйте датчик на GPIO4
echo 4 | sudo tee /proc/sensors/dht/export

# 5. Читайте температуру и влажность
cat /proc/sensors/dht/gpio4/value

# 6. Включите автопросрос каждые 5 секунд
echo 5 | sudo tee /proc/sensors/dht/gpio4/interval

# 7. Или включите глобальный автопросрос для всех датчиков
echo 10 | sudo tee /proc/sensors/dht/auto_interval

# 8. Проверьте версию драйвера
cat /proc/sensors/dht/version

# 9. Выгрузите по окончании
sudo rmmod dht
```

## Сборка и установка

### Предварительные требования

```bash
# Raspberry Pi OS / Debian / Ubuntu
sudo apt install build-essential linux-headers-$(uname -r)
```

### Нативная сборка

```bash
make            # проверка перед сборкой, затем сборка dht.ko
make check      # только проверка
make modules    # сборка без проверки
make clean      # удалить артефакты сборки
```

### Установка (нативная)

```bash
make install    # сборка, установка в /lib/modules/$(uname -r)/, depmod
sudo modprobe dht
```

Модуль устанавливается в `/lib/modules/$(uname -r)/updates/`. Это стандартное расположение для внешних модулей, имеющее приоритет над `/kernel/` при поиске `modprobe`.

### Удаление

```bash
make uninstall   # ищет и удаляет dht.ko во всех каталогах модулей
sudo modprobe -r dht
```

Цель `uninstall` использует `find` для поиска по всем подкаталогам `/lib/modules/$(uname -r)/` (включая `updates/`, `kernel/`, `extra/`), корректно удаляя модуль независимо от места установки.

### Кросс-компиляция

```bash
# Пример: сборка на x86 для Raspberry Pi 5 (arm64)
make ARCH=arm64 \
     CROSS_COMPILE=aarch64-linux-gnu- \
     KDIR=/path/to/rpi-kernel/build

# Установка в примонтированную целевую ФС
make ARCH=arm64 \
     CROSS_COMPILE=aarch64-linux-gnu- \
     KDIR=/path/to/rpi-kernel/build \
     INSTALL_MOD_PATH=/mnt/rpi-root \
     install
```

### Цели Make

| Цель            | Описание                                                |
|-----------------|---------------------------------------------------------|
| `make`          | Проверка перед сборкой, затем сборка модуля             |
| `make check`    | Только проверка (заголовки, версия ядра)                |
| `make modules`  | Сборка `dht.ko` без проверки                            |
| `make clean`    | Удалить артефакты сборки                                 |
| `make install`  | Сборка, установка в `/lib/modules/...`, `depmod`         |
| `make uninstall`| Поиск и удаление `dht.ko` из всех каталогов              |
| `make help`     | Показать доступные цели и переменные                    |

## Установка через DKMS

DKMS (Dynamic Kernel Module Support) автоматически пересобирает модуль при обновлении ядра, избавляя от ручной пересборки после `apt upgrade`.

### Предварительные требования

```bash
sudo apt install dkms
```

### Установка

```bash
# 1. Скопируйте файлы драйвера в исходное дерево DKMS
sudo mkdir -p /usr/src/dht-2.9
sudo cp dht.c Makefile dkms.conf /usr/src/dht-2.9/

# 2. Зарегистрируйте модуль в DKMS
sudo dkms add dht/2.9

# 3. Соберите и установите
sudo dkms install dht/2.9

# 4. Загрузите модуль
sudo modprobe dht
```

### Проверка

```bash
# Проверьте статус DKMS
sudo dkms status
# Ожидаемый вывод: dht/2.9: installed

# Проверьте, что модуль загружен
lsmod | grep dht
cat /proc/sensors/dht/version
```

### Автоматическая пересборка

С `AUTOINSTALL="yes"` в `dkms.conf` модуль автоматически пересобирается при установке нового ядра.

### Обновление до новой версии драйвера

```bash
# 1. Удалите старую версию
sudo dkms remove dht/2.9 --all

# 2. Скопируйте новые файлы
sudo cp dht.c Makefile dkms.conf /usr/src/dht-2.9/

# 3. Переустановите
sudo dkms install dht/2.9
```

### Полное удаление

```bash
sudo dkms remove dht/2.9 --all
sudo rm -rf /usr/src/dht-2.9
```

### dkms.conf

```ini
PACKAGE_NAME="dht"
PACKAGE_VERSION="2.9"
BUILT_MODULE_NAME[0]="dht"
DEST_MODULE_LOCATION[0]="/updates"
AUTOINSTALL="yes"
MAKE[0]="make -C ${kernel_source_dir} M=${dkms_tree}/${PACKAGE_NAME}/${PACKAGE_VERSION}/build modules"
CLEAN[0]="make -C ${kernel_source_dir} M=${dkms_tree}/${PACKAGE_NAME}/${PACKAGE_VERSION}/build clean"
```

## Совместимость с ядрами

Драйвер поддерживает ядра Linux от 5.0 до 6.18+. Различия в API между версиями ядра обрабатываются на этапе компиляции с помощью препроцессорных макросов — скрипт `configure` не требуется.

### API-шеймы совместимости

#### proc_ops / file_operations (ядро 5.6)

Начиная с ядра 5.6, `proc_create()` принимает `const struct proc_ops *` вместо `const struct file_operations *`. Имена полей также изменились: `.read` -> `.proc_read` и т.д.

```c
#if LINUX_VERSION_CODE >= KERNEL_VERSION(5, 6, 0)
  #define DHT_PROC_OPS     struct proc_ops
  #define DHT_PROC_READ    .proc_read
  #define DHT_PROC_WRITE   .proc_write
  #define DHT_PROC_OPEN    .proc_open
  #define DHT_PROC_RELEASE .proc_release
#else
  #define DHT_PROC_OPS     struct file_operations
  #define DHT_PROC_READ    .read
  #define DHT_PROC_WRITE   .write
  #define DHT_PROC_OPEN    .open
  #define DHT_PROC_RELEASE .release
#endif
```

Все структуры `proc_ops`/`file_operations` в драйвере используют `DHT_PROC_OPS` вместо прямого имени типа.

#### pde_data / PDE_DATA (ядро 5.17)

Начиная с ядра 5.17, `PDE_DATA()` переименована в `pde_data()`.

```c
#if LINUX_VERSION_CODE >= KERNEL_VERSION(5, 17, 0)
  #define DHT_PDE_DATA(inode)  pde_data(inode)
#else
  #define DHT_PDE_DATA(inode)  PDE_DATA(inode)
#endif
```

### Проверка перед сборкой

Цель `check` в Makefile проверяет перед компиляцией:

- Каталог сборки ядра существует и содержит допустимое дерево Kbuild
- Версия ядра >= 5.0
- Предупреждает, если `ARCH=` задан без `CROSS_COMPILE=` (и наоборот)

> **Примечание:** Драйвер требует включённых `CONFIG_GPIOLIB`, `CONFIG_PROC_FS` и `CONFIG_MODULES` в ядре во время выполнения. Цель `make check` не проверяет эти параметры — они проверяются неявно при загрузке модуля.

## Файл конфигурации

Драйвер читает опциональный файл конфигурации `/etc/default/dht` при загрузке. Если файл отсутствует, драйвер загружается с настройками по умолчанию. Строки, начинающиеся с `#`, и пустые строки игнорируются. Неизвестные параметры и недопустимые значения вызывают предупреждения в dmesg.

### Глобальные параметры

```
DEBUG                - включить отладку при загрузке (аналог DEBUG=1)
DEBUG=0|1            - явно выключить/включить отладку
AUTO_INTERVAL=n      - глобальный интервал автопроса в секундах (2-60)
                       Запускает опрос для всех зарегистрированных датчиков
```

### Регистрация датчиков

```
SENSOR=<pin>         - зарегистрировать датчик на BCM пине
SENSOR=<pin>,<n>     - зарегистрировать с индивидуальным интервалом автопроса
                       (2-60 секунд; -1 отключает автопрос)
```

### Пример

```
# /etc/default/dht
DEBUG=1
AUTO_INTERVAL=10
SENSOR=4             - DHT22 на GPIO4, использует глобальный интервал
SENSOR=17,5          - DHT11 на GPIO17, опрос каждые 5 секунд
SENSOR=22            - Датчик на GPIO22, без автопроса
```

## Интерфейс procfs

### Глобальные записи

```
/proc/sensors/dht/
  debug         (rw) - журнал отладки: 0 = выкл (по умолч.), 1 = вкл
  version       (r)  - версия драйвера
  export        (w)  - записать номер BCM пина для регистрации датчика
  unexport      (w)  - записать номер BCM пина для удаления датчика
  auto_interval (rw) - глобальный интервал автопроса (2-60, -1 = выкл)
```

### Записи датчиков

```
/proc/sensors/dht/gpio<pin>/
  pin           (r)  - номер BCM GPIO пина
  interval      (rw) - интервал автопроса в секундах (2-60, -1 = выкл)
  measure       (w)  - записать "1" для запуска измерения
                       (игнорируется, если interval != -1 или активен глобальный автопрос)
  status_code   (r)  - код ошибки (0 = успех)
  status_text   (r)  - описание ошибки
  value         (r)  - "H=<влажность>\nT=<температура>\n"
  info          (r)  - тип датчика + время регистрации
  timestamp     (r)  - Unix-метка времени последнего измерения
```

## Автоматический опрос

### Индивидуальный интервал

```bash
echo 5 | sudo tee /proc/sensors/dht/gpio4/interval
# Опрос каждые 5 секунд для датчика на GPIO4
```

### Глобальный интервал

```bash
echo 10 | sudo tee /proc/sensors/dht/auto_interval
# Опрос каждые 10 секунд для всех датчиков
```

### Отключение

```bash
echo -1 | sudo tee /proc/sensors/dht/gpio4/interval
# Отключить индивидуальный автопрос

echo -1 | sudo tee /proc/sensors/dht/auto_interval
# Отключить глобальный автопрос
```

### Приоритет интервалов

1. Глобальный `auto_interval` (если != -1) имеет приоритет над индивидуальным
2. Индивидуальный `interval` (если != -1) используется, если глобальный отключён
3. Если оба -1, автопрос отсутствует — только ручные измерения

## Ручное измерение

```bash
echo 1 | sudo tee /proc/sensors/dht/gpio4/measure
# Запускает измерение
```

Ручное измерение игнорируется, если:
- Индивидуальный `interval` != -1 (активен автопрос)
- Глобальный `auto_interval` != -1 (активен глобальный автопрос)
- С момента последнего измерения прошло менее `MEAS_MIN_GAP` секунд (2 с)

## Определение типа датчика

Драйвер автоматически определяет тип датчика (DHT11 или DHT22/AM2302) по результатам первого успешного измерения:

- **DHT11**: если дробные байты (байты 1 и 3) равны 0, а целые в диапазоне 0–100 для влажности
- **DHT22/AM2302**: в остальных случаях

Тип отображается в записи `info`:
```bash
cat /proc/sensors/dht/gpio4/info
# Sensor: DHT22
# Registered: 2026-01-15T14:30:00Z
```

До первого успешного измерения тип — `Unknown`.

## Примеры на Python

```python
#!/usr/bin/env python3
import time

PIN = 4
VALUE_PATH = f"/proc/sensors/dht/gpio{PIN}/value"

def read_sensor():
    with open(VALUE_PATH) as f:
        data = f.read()
    result = {}
    for line in data.strip().split('\n'):
        key, val = line.split('=')
        result[key] = float(val)
    return result

with open("/proc/sensors/dht/export", 'w') as f:
    f.write(str(PIN))

with open(f"/proc/sensors/dht/gpio{PIN}/interval", 'w') as f:
    f.write("5")

while True:
    data = read_sensor()
    print(f"H={data['H']:.1f}%  T={data['T']:.1f}C")
    time.sleep(5)
```

## Архитектура

### Структуры данных

- `struct dht_sensor` — представляет один зарегистрированный датчик (пин, результаты, поток опроса, procfs-записи, мьютекс)
- Глобальный связный список `sensor_list` всех активных датчиков, защищённый `list_lock` (мьютекс)
- `kref` для управления жизненным циклом: счётчик ссылок на список + по одной на каждый открытый procfs-файл

### Поток опроса

Каждый датчик с активным интервалом имеет собственный поток ядра (`kthread`):
- Цикл: измерение -> ожидание интервала -> повтор
- `kthread_should_stop()` проверяется между итерациями
- `kthread_stop()` вызывается **вне** `list_lock` для предотвращения сна под блокировкой

### Регистрация (export)

1. Проверка пина (0–27, не дубликат)
2. Выделение `struct dht_sensor`, запрос GPIO
3. Дополнительная проверка дубликата под `list_lock` (защита от TOCTOU)
4. Создание procfs-записей
5. Добавление в `sensor_list`

### Удаление (unexport)

1. Удаление из `sensor_list` под `list_lock`
2. Освобождение `list_lock`
3. Остановка потока опроса (`kthread_stop` без `list_lock`)
4. `dht_sensor_put` — освобождение через kref

### Выгрузка модуля

1. Фаза 1: `proc_remove` для всех procfs-записей (закрывает новые обращения)
2. Фаза 2: удаление всех датчиков из списка, остановка потоков, освобождение ресурсов
3. Удаление `/proc/sensors/dht/`
4. Удаление `/proc/sensors/` (если нет других драйверов)

## Известные ограничения

- Макс. 32 одновременных датчика
- BCM пины 0–27 (Raspberry Pi)
- Мин. интервал между измерениями: 2 секунды (аппаратное ограничение DHT)
- Bit-bang чтение отключает вытеснение (~4 мс) — может влиять на реальное время
- Прерывания остаются включёнными во время чтения
- Не поддерживается hot-plug GPIO-чипа
- `/proc/sensors` разделяется с другими драйверами — удаляется только если пуст

## Устранение неполадок

| Симптом                              | Причина                        | Решение                                      |
|--------------------------------------|--------------------------------|----------------------------------------------|
| `make` не находит заголовки ядра      | Нет `linux-headers`            | `sudo apt install linux-headers-$(uname -r)` |
| `make`: версия ядра слишком старая    | Ядро < 5.0                    | Обновить ядро или использовать старую версию  |
| `implicit declaration of 'proc_read'` | Ядро < 5.6, нет шейма          | Проверить `DHT_PROC_OPS` в `dht.c`            |
| `make` не создаёт `dht.ko`            | `obj-m` не на верхнем уровне   | `obj-m += dht.o` перед `ifdef KERNELRELEASE`  |
| `WARNING: ARCH= but CROSS_COMPILE=`   | Несовпадение кросс-компиляции  | Задать оба `ARCH` и `CROSS_COMPILE`           |
| Ошибка сборки DKMS                    | Нет `dkms.conf` или заголовков | `sudo apt install dkms linux-headers-...`     |
| Модуль не загружается                 | GPIO не в ядре                 | Включить `CONFIG_GPIOLIB` в конфигурации ядра|
| Чтение всегда неуспешно (status=3)    | Проводка, подтяжка, тайминги   | Проверить проводку, добавить подтяжку 4.7–10 кОм |
| Прерывистые ошибки чтения             | Нагрузка во время bit-bang      | Включить автопросрос, снизить нагрузку        |
| Неправильная отрицательная температура| Обработка знакового бита       | Исправлено в 2.8.3 (маска перед отрицанием)  |
| `modprobe: dht not found`             | Модуль не установлен           | `make install` или установка через DKMS       |
| `rmmod: Module dht is in use`         | Procfs-файл ещё открыт         | Закрыть все файлы `/proc/sensors/dht/`       |
| Датчик не определён                   | Нет успешного измерения        | Проверить проводку, попробовать `echo 1 > measure` |
| `PDE_DATA` implicit declaration      | Ядро >= 5.17, старый код       | Использовать макрос `DHT_PDE_DATA`           |
