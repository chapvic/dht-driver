# DHT Driver — Драйвер датчиков DHT11/DHT22/AM2302

Драйвер ядра Linux для чтения температуры и влажности с датчиков DHT11, DHT22 и AM2302, подключённых к GPIO-пинам Raspberry Pi. Драйвер создаёт интерфейс procfs в `/proc/sensors/dht/` для управления регистрацией датчиков, настройки и получения данных.

- **Версия драйвера:** 2.5
- **Автор:** Chapvic © 2026
- **Лицензия:** GPL v3

## Поддерживаемое оборудование

### Датчики

| Датчик | Температура | Влажность | Разрешение | Особенности |
|--------|-------------|-----------|------------|-------------|
| DHT11 | 0…50 °C | 20…90% | 1 °C / 1% | Целочисленные значения, простейший протокол |
| DHT22 (AM2302) | −40…80 °C | 0…100% | 0.1 °C / 0.1% | Десятичные значения, расширенный диапазон |
| AM2302 | −40…80 °C | 0…100% | 0.1 °C / 0.1% | DHT22 в выносном корпусе с проводом |

Тип датчика определяется **автоматически** по формату данных: если влажность превышает 1000 (в десятых долях), датчик идентифицируется как DHT11, иначе как DHT22.

### Одноплатные компьютеры

| Модель | GPIO-чип | Базовый номер | Метод обнаружения |
|--------|----------|---------------|-------------------|
| Raspberry Pi 3 | bcm2835 | 512 | Прямой поиск + сканирование |
| Raspberry Pi 4 | bcm2711 | 512 | Прямой поиск + сканирование |
| Raspberry Pi 5 | pinctrl-rp1 | 571 | Сканирование (прямой поиск не работает) |

Драйвер кэширует базовый номер GPIO-чипа при первой регистрации датчика. Последующие регистрации используют кэш — один вызов `gpio_to_desc()` вместо сканирования до 2048 номеров.

## Сборка и установка

### Требования

- Заголовочные файлы ядра (`linux-headers`) для текущей версии ядра
- Компилятор `gcc` / `make`
- Права root для загрузки модуля

### Сборка

```bash
make -C /lib/modules/$(uname -r)/build M=$(pwd) modules
```

Результат — файл `dht.ko`.

### Установка и загрузка

```bash
# Загрузка модуля
sudo insmod dht.ko

# Загрузка с включённой отладкой
sudo insmod dht.ko dht_debug=1

# Проверка загрузки
dmesg | tail -5
```

Ожидаемый вывод dmesg:

```
[DHT]: DHT Driver © 2026, Chapvic (v2.5)
[DHT]: driver loaded - /proc/sensors/dht/ (max 32 sensors)
```

### Выгрузка модуля

```bash
sudo rmmod dht
```

### Автозагрузка (опционально)

```bash
sudo cp dht.ko /lib/modules/$(uname -r)/extra/
sudo depmod -a
echo "dht" | sudo tee /etc/modules-load.d/dht.conf
```

## Интерфейс procfs

Драйвер создаёт два уровня записей в procfs.

### Глобальные записи: `/proc/sensors/dht/`

| Запись | Права | Описание |
|--------|-------|----------|
| `debug` | rw (0666) | Включение/выключение отладочного вывода: 0 = выкл (по умолчанию), 1 = вкл |
| `version` | r (0444) | Версия драйвера |
| `export` | w (0222) | Запись BCM-номера пина для регистрации датчика |
| `unexport` | w (0222) | Запись BCM-номера пина для удаления датчика |
| `auto_interval` | rw (0666) | Глобальный интервал автоопроса в секундах (2–60), −1 = выключен |

### Записи датчика: `/proc/sensors/dht/gpio<pin>/`

| Запись | Права | Описание |
|--------|-------|----------|
| `pin` | r (0444) | BCM-номер GPIO-пина |
| `interval` | rw (0644) | Интервал автоопроса в секундах (2–60), −1 = выключен |
| `measure` | w (0222) | Запись `1` для ручного измерения (игнорируется, если включён автоопрос) |
| `status_code` | r (0444) | Код ошибки (0 = успех) |
| `status_text` | r (0444) | Текстовое описание ошибки |
| `value` | r (0444) | Значения: `H=<влажность>\nT=<температура>\n` |
| `info` | r (0444) | Тип датчика и время регистрации (ISO 8601) |
| `timestamp` | r (0444) | Unix-метка времени последнего измерения |

### Формат значения

Запись `value` возвращает данные в формате с десятыми долями:

```
H=45.2
T=23.1
```

Для отрицательных температур знак минуса ставится перед целой частью:

```
H=45.2
T=-5.3
```

## Быстрый старт

```bash
# 1. Загрузка драйвера
sudo insmod dht.ko

# 2. Регистрация датчика на GPIO 23
echo 23 | sudo tee /proc/sensors/dht/export

# 3. Ручное измерение
echo 1 | sudo tee /proc/sensors/dht/gpio23/measure

# 4. Чтение данных
cat /proc/sensors/dht/gpio23/value

# 5. Удаление датчика
echo 23 | sudo tee /proc/sensors/dht/unexport
```

## Примеры использования

### Регистрация датчика

```bash
echo 23 | sudo tee /proc/sensors/dht/export
```

Вывод dmesg:

```
[dht_gpio_23]: found on 'pinctrl-bcm2835' (base=512, global=535)
[dht_gpio_23]: registered successfully
```

При регистрации драйвер автоматически выполняет первое измерение для проверки работоспособности датчика. Если измерение не удалось, регистрация отменяется и возвращается ошибка `EIO`.

### Ручное измерение

```bash
echo 1 | sudo tee /proc/sensors/dht/gpio23/measure
cat /proc/sensors/dht/gpio23/value
```

Вывод:

```
H=45.2
T=23.1
```

Ручное измерение недоступно, если для датчика включён автоопрос (локальный или глобальный интервал ≠ −1). В этом случае запись в `measure` возвращает код ошибки `ERR_AUTO_MODE`.

Защита от частых запросов: между ручными измерениями должно пройти не менее 2 секунд.

### Автоопрос (индивидуальный)

```bash
# Включить автоопрос каждые 5 секунд
echo 5 | sudo tee /proc/sensors/dht/gpio23/interval

# Проверка
cat /proc/sensors/dht/gpio23/interval
```

Вывод dmesg:

```
[dht_gpio_23]: auto-poll enabled (interval=5)
```

Драйвер создаёт поток ядра `dht_poll_23`, который каждые 5 секунд выполняет измерение и обновляет данные. Результаты доступны через `value`, `status_code`, `status_text`, `timestamp`.

```bash
# Выключить автоопрос
echo -1 | sudo tee /proc/sensors/dht/gpio23/interval
```

### Автоопрос (глобальный)

Глобальный режим включает автоопрос сразу для **всех** зарегистрированных датчиков с одинаковым интервалом. Индивидуальные настройки `interval` при этом игнорируются.

```bash
# Включить глобальный автоопрос каждые 10 секунд
echo 10 | sudo tee /proc/sensors/dht/auto_interval

# Проверка
cat /proc/sensors/dht/auto_interval
```

Вывод dmesg:

```
[DHT]: auto_interval set to 10
[dht_gpio_23]: auto-poll enabled by global setting
```

```bash
# Выключить глобальный автоопрос
echo -1 | sudo tee /proc/sensors/dht/auto_interval
```

При выключении глобального режима потоки опроса останавливаются, если индивидуальный `interval` тоже равен −1.

### Несколько датчиков

```bash
echo 23 | sudo tee /proc/sensors/dht/export
echo 24 | sudo tee /proc/sensors/dht/export
echo 25 | sudo tee /proc/sensors/dht/export

# Глобальный автоопрос для всех
echo 5 | sudo tee /proc/sensors/dht/auto_interval

# Чтение данных
cat /proc/sensors/dht/gpio23/value
cat /proc/sensors/dht/gpio24/value
cat /proc/sensors/dht/gpio25/value
```

При регистрации второго и последующих датчиков используется кэш базового номера GPIO-чипа — сканирование не повторяется.

Вывод dmesg при регистрации второго датчика:

```
[dht_gpio_24]: found on 'pinctrl-bcm2835' (base=512, global=536)
[dht_gpio_24]: registered successfully
```

### Статус и информация о датчике

```bash
# Код ошибки
cat /proc/sensors/dht/gpio23/status_code
# Вывод: 0

# Текстовое описание
cat /proc/sensors/dht/gpio23/status_text
# Вывод: SUCCESS

# Информация о датчике
cat /proc/sensors/dht/gpio23/info
# Вывод:
# Sensor type: DHT11
# Register time: 2026-09-18T14:30:00Z

# Метка времени последнего измерения
cat /proc/sensors/dht/gpio23/timestamp
# Вывод: 1742590200
```

### Удаление датчика

```bash
echo 23 | sudo tee /proc/sensors/dht/unexport
```

Вывод dmesg:

```
[dht_gpio_23]: unregistered
```

Сообщение об удалении выводится в dmesg **всегда**, независимо от состояния режима отладки.

### Дублирование регистрации

```bash
echo 23 | sudo tee /proc/sensors/dht/export
echo 23 | sudo tee /proc/sensors/dht/export  # повторно
# tee: /proc/sensors/dht/export: Device or resource busy
```

Вывод dmesg (только при включённой отладке):

```
[DHT]: pin 23 already registered
```

При включённой отладке (`dht_debug=1` или `echo 1 > /proc/sensors/dht/debug`) драйвер выводит в dmesg подробную диагностическую информацию.

### Пример вывода при успешном измерении

```

[dht_gpio_23]: measurement OK - H=45.2% T=23.1 C

[dht_gpio_23]: poll thread started
[dht_gpio_23]: measurement OK - H=45.1% T=23.0 C
[dht_gpio_23]: measurement OK - H=45.3% T=23.1 C
```

### Пример вывода при ошибке чтения

```
[dht_gpio_23]: read attempt 1 failed - j=39, data=[35,0,48,0,59]
[dht_gpio_23]: read attempt 2 failed - j=38, data=[0,0,0,0,0]

```

## Коды ошибок

| Код | Константа | Описание |
|-----|-----------|----------|
| 0 | `ERR_SUCCESS` | Успех |
| 1 | `ERR_PIN_INVALID` | Неверный номер пина (должен быть 0–27) |
| 2 | `ERR_GPIO_REQUEST` | Ошибка запроса или поиска GPIO |
| 3 | `ERR_READ_FAILED` | Ошибка чтения данных с датчика |
| 4 | `ERR_AUTO_MODE` | Ручное измерение недоступно в режиме автоопроса |
| 5 | `ERR_TOO_SOON` | Слишком частый запрос (минимум 2 секунды между измерениями) |

Код ошибки доступен через `/proc/sensors/dht/gpio<pin>/status_code`, текстовое описание — через `status_text`.

## Технические детали

### Протокол DHT

Датчики DHT используют однопроводный протокол с одной линией данных. Обмен состоит из следующих этапов:

1. **Старт-сигнал** — драйвер устанавливает линию в низкий уровень на 20 мс, затем отпускает (переключает пин на вход).
2. **Ответ датчика** — датчик тянет линину вниз на ~80 мкс, затем поднимает на ~80 мкс.
3. **Передача данных** — 40 бит (5 байт): влажность (старший + младший байт), температура (старший + младший байт), контрольная сумма.
4. **Кодирование битов** — каждый бит начинается с ~50 мкс низкого уровня, затем высокий уровень: ~26 мкс для нуля, ~70 мкс для единицы.
5. **Контрольная сумма** — сумма первых четырёх байт по модулю 256 должна равняться пятому байту.

### Формат данных

**DHT11:**
- Байт 0: влажность (целая часть)
- Байт 1: влажность (дробная часть, обычно 0)
- Байт 2: температура (целая часть)
- Байт 3: температура (дробная часть, обычно 0)
- Байт 4: контрольная сумма

**DHT22/AM2302:**
- Байты 0–1: влажность × 10 (16 бит, big-endian)
- Байты 2–3: температура × 10 (16 бит, big-endian, старший бит = знак)
- Байт 4: контрольная сумма

### Наносекундный тайминг

Драйвер использует `ktime_get_ns()` для измерения длительности каждого импульса с точностью до наносекунд. Порог различения нуля и единицы — 40 мкс (`BIT_THRESHOLD`), что находится ровно между длительностью нуля (~26 мкс) и единицы (~70 мкс). Это обеспечивает корректную работу на любой модели Raspberry Pi независимо от скорости процессора.

Таймаут ожидания импульса — 200 мкс (`PULSE_TIMEOUT_NS`). Если за это время состояние линии не меняется, цикл чтения прерывается — это предотвращает зависание при отключённом или неисправном датчике.

### Обнаружение GPIO-чипа

На Raspberry Pi 5 GPIO-чип имеет базовый номер 571 (чип `pinctrl-rp1`), а не 0, как на Pi 3/4. Драйвер определяет чип тремя способами:

1. **Кэш** — если базовый номер уже определён при предыдущей регистрации, используется `gpio_to_desc(base + bcm_pin)`. Быстрый путь — один вызов.
2. **Прямой поиск** — `gpio_to_desc(bcm_pin)`. Работает на Pi 3/4 (base = 0 или 512, где BCM-номер совпадает со смещением).
3. **Полное сканирование** — перебор глобальных номеров от 0 до 2048, поиск чипа с меткой `rp1`, `bcm2835`, `bcm2711` или `bcm2712`. Выполняется один раз, результат кэшируется.

Распознавание чипа выполняется по подстроке в метке: `pinctrl-rp1` (Pi 5), `pinctrl-bcm2835` (Pi 3), `pinctrl-bcm2711` (Pi 4), `pinctrl-bcm2712` (Pi 5 альтернативный).

### Архитектура опроса

Каждый датчик с включённым автоопросом получает собственный поток ядра (`kthread`), named `dht_poll_<pin>`. Поток выполняет измерение, затем засыпает на `effective_interval` секунд с проверкой `kthread_should_stop()` каждую секунду — это обеспечивает быструю остановку потока при удалении датчика или выгрузке модуля.

Эффективный интервал:
- Если глобальный `auto_interval` ≠ −1 — используется глобальное значение.
- Иначе — индивидуальное значение `interval` датчика.
- Если значение меньше `MIN_INTERVAL` — используется `MIN_INTERVAL`.

### Стратегия блокировок

- **`list_lock`** — защищает глобальный список датчиков и счётчик `sensor_count`. Берётся при добавлении/удалении датчика и при включении глобального автоопроса.
- **`sensor->lock`** — защищает состояние отдельного датчика (результаты измерений, интервал, статус). Берётся на короткое время: запись результатов, чтение значений для procfs.
- **Длительная операция чтения датчика** (`dht_read_sensor`, ~20 мс) выполняется **без блокировки** — это предотвращает дедлоки и блокировку procfs на время измерения.
- **Переменные write-once** (`cached_chip_base`, `dht_debug`, `global_auto_interval`) используют `READ_ONCE`/`WRITE_ONCE` — корректны без мьютексов.

### Rate limiting

Ручные измерения ограничены: между запросами должно пройти не менее 2 секунд (`MEAS_MIN_GAP`). Время последней попытки фиксируется в `last_attempt_time`. При слишком частом запросе возвращается `ERR_TOO_SOON`.

Для автоопроса rate limiting не применяется — поток опроса сам гарантирует интервал.

### Логика повторов

При ошибке чтения драйвер делает до 3 попыток (`MAX_RETRIES`) с задержкой 100 мс (`RETRY_DELAY_MS`) между ними. DHT11 часто не отвечает с первого раза, особенно сразу после загрузки модуля. Если все попытки неудачны, возвращается `ERR_READ_FAILED`.

### Автоопределение типа сенсора

Тип датчика определяется по формату полученных данных, а не по явному указанию:

- Если значение влажности > 1000 (десятых долей) — **DHT11** (формат: целая часть в первом байте, дробная во втором).
- Иначе — **DHT22** (формат: 16-битное значение, старший байт первым).
- Для DHT11 при влажности > 100.0% значение пересчитывается в целую часть × 10.
- Для DHT22 при температуре > 125.0 °C значение пересчитывается аналогично.
- Знак температуры определяется по старшему биту третьего байта.

### Совместимость procfs

Драйвер поддерживает два API procfs в зависимости от версии ядра:

- **Ядро ≥ 5.6** — `struct proc_ops` с полями `.proc_read` / `.proc_write`.
- **Ядро < 5.6** — `struct file_operations` с полями `.read` / `.write`.

Также поддерживается изменение API получения данных inode:

- **Ядро ≥ 5.17** — `pde_data(inode)`.
- **Ядро < 5.17** — `PDE_DATA(inode)`.

Совместимость обеспечивается макросами `DHT_PROC_OPS`, `DHT_PROC_READ`, `DHT_PROC_WRITE` и `DHT_PDE_DATA`.

---

## Ограничения и замечания

- **Максимум 32 датчика** — ограничение `MAX_SENSORS`, изменяется в исходном коде.
- **BCM-номера 0–27** — поддерживаются только стандартные GPIO-пины Raspberry Pi.
- **Интервал 2–60 секунд** — минимум и максимум для автоопроса.
- **DHT11: частота опроса** — производитель рекомендует не чаще 1 раза в секунду. Драйвер устанавливает минимум 2 секунды.
- **DHT22: частота опроса** — производитель рекомендует не чаще 1 раза в 2 секунды. Минимум 2 секунды соблюдён.
- **Только один датчик на пин** — повторная регистрация на том же пине возвращает `EBUSY`.
- **Поток ядра на датчик** — каждый датчик с автоопросом создаёт отдельный kthread. При 32 датчиках и глобальном автоопросе будет 32 потока.
- **Pull-up резистор** — датчики DHT требуют подтягивающего резистора 4.7–10 кОм между линией данных и VCC. Большинство готовых модулей DHT11/DHT22 уже содержат резистор на плате.
- **Невозможность одновременной регистрации на одном пине** — проверяется под `list_lock`.

## Устранение неполадок

### Датчик не регистрируется: `Input/output error`

```
[dht_gpio_23]: read failed after 3 attempts - j=0, data=[0,0,0,0,0]
[dht_gpio_23]: registration failed - Sensor data read failed
```

**Причины и решения:**

- Датчик не подключён или подключён не к тому пину. Проверьте схему подключения.
- Нет pull-up резистора. Добавьте резистор 4.7–10 кОм между DATA и VCC.
- Несовпадение номера пина. Драйвер использует **BCM-номера**, а не физические (BOARD) номера. BCM 23 = физический пин 16.
- Датчик неисправен. Попробуйте другой датчик.

### Ошибка: `Device or resource busy` при регистрации

Датчик на этом пине уже зарегистрирован. Сначала удалите его:

```bash
echo 23 | sudo tee /proc/sensors/dht/unexport
```

### Датчик зарегистрирован, но данные не обновляются

Проверьте статус:

```bash
cat /proc/sensors/dht/gpio23/status_code
cat /proc/sensors/dht/gpio23/status_text
```

Если `status_code` ≠ 0, последнее измерение не удалось. Включите отладку для диагностики:

```bash
echo 1 | sudo tee /proc/sensors/dht/debug
echo 1 | sudo tee /proc/sensors/dht/gpio23/measure
dmesg | tail -20
```

### Ручное измерение возвращает `ERR_AUTO_MODE`

Ручное измерение недоступно при включённом автоопросе. Выключите его:

```bash
echo -1 | sudo tee /proc/sensors/dht/gpio23/interval
echo -1 | sudo tee /proc/sensors/dht/auto_interval
```

### Данные intermittently неверны

DHT11/DHT22 — дешёвые датчики с погрешностью. Единичные неверные показания нормальны. Включите автоопрос — драйвер обновит данные при следующем цикле. Контрольная сумма отсеивает большинство битых чтений.

### `gpio descriptor not found` в dmesg

Драйвер не нашёл GPIO-чип Raspberry Pi. Проверьте, что загружено правильное ядро с поддержкой GPIO. Выполните:

```bash
cat /sys/kernel/debug/gpio | head -20
```

### Ошибка `Too soon since last measurement`

Ручные измерения ограничены — минимум 2 секунды между запросами. Подождите и повторите.

### Драйвер не загружается: `No such file or directory`

```bash
sudo insmod dht.ko
# insmod: ERROR: could not insert module dht.ko: No such file or directory
```

Проверьте, что файл `dht.ko` существует в текущей директории. Если нет — пересоберите драйвер.

### Ошибка компиляции

Убедитесь, что установлены заголовочные файлы ядра:

```bash
sudo apt install linux-headers-$(uname -r)
```

И что путь в Makefile указывает на правильную директорию сборки.
