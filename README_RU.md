## Обзор

Драйвер ядра Linux для чтения температуры и влажности с датчиков DHT11, DHT22 и AM2302, подключённых к GPIO-пинам Raspberry Pi. Драйвер создаёт интерфейс procfs в `/proc/sensors/dht/` для управления регистрацией датчиков, настройки и получения данных.

### Ключевые возможности

- Динамическая регистрация и удаление датчиков через procfs
- Индивидуальные proc-записи для каждого датчика: температура, влажность, статус, конфигурация
- Фоновый поток опроса с настраиваемым интервалом
- Глобальный режим автоопроса с общим интервалом
- Кэширование базы GPIO-чипа для быстрой регистрации нескольких датчиков на Pi 3/4/5
- Наносекундная точность измерения импульсов для надёжного чтения на всех моделях Pi
- Ограничение частоты измерений (rate limiting) для ручных и автоматических опросов
- Безопасная выгрузка модуля со счётом ссылок
- Совместное использование `/proc/sensors` с другими драйверами датчиков
- Файл конфигурации: опциональный `/etc/default/dht` для авто-регистрации при загрузке

## Поддерживаемое оборудование

### Датчики

| Датчик | Влажность | Температура | Особенности |
|--------|-----------|-------------|-------------|
| DHT11 | 20–90% ±5% | 0–50 °C ±2 °C | Целочисленные значения, более низкое разрешение |
| DHT22 (AM2302) | 0–100% ±2% | −40–80 °C ±0.5 °C | Десятичные значения, более высокое разрешение |
| AM2302 | 0–100% ±2% | −40–80 °C ±0.5 °C | DHT22 в защищённом корпусе |

Драйвер автоматически определяет тип датчика по формату данных после первого успешного измерения.

### Модели Raspberry Pi

| Модель | GPIO-чип | Метка | Base offset |
|--------|----------|-------|-------------|
| Pi 5 | RP1 | `pinctrl-rp1` | ≥ 512 |
| Pi 4 | BCM2711 | `pinctrl-bcm2711` | 0 |
| Pi 3 | BCM2835 | `pinctrl-bcm2835` | 0 |
| Pi 2 | BCM2835 | `pinctrl-bcm2835` | 0 |
| Pi 1 / Zero | BCM2835 | `pinctrl-bcm2835` | 0 |

### Совместимость ядра

- Минимальная версия ядра: 5.10
- Архитектура: ARM64 (aarch64), ARM (armhf)
- Тестированные комбинации: Pi 3/4/5 с ядрами 5.10–6.18

## Подключение

### Схема

```
DHT датчик          Raspberry Pi
──────────          ─────────────
VCC  ────────────── 3.3V (пин 1)
DATA ──[резистор]── GPIO (BCM номер)
GND  ────────────── GND (пин 6)
```

### Подтягивающий резистор

Датчик DATA подключается к GPIO-пину через подтягивающий резистор 4.7–10 кОм (между DATA и VCC). Многие готовые модули DHT (например, AM2302) уже имеют встроенный резистор.

### Выбор пинов

Драйвер поддерживает BCM-номера пинов от 0 до 27. Рекомендуемые пины: GPIO4 (физический пин 7), GPIO17 (пин 11), GPIO22 (пин 15), GPIO23 (пин 16), GPIO24 (пин 18), GPIO25 (пин 22).

## Быстрый старт

### 1. Установка заголовочных файлов ядра

```bash
sudo apt install linux-headers-$(uname -r) build-essential
```

### 2. Сборка модуля

```bash
cd /path/to/dht_driver
make
```

### 3. Установка модуля

```bash
sudo make install
sudo depmod -a
```

### 4. Загрузка модуля

```bash
sudo modprobe dht
```

Проверьте, что модуль загрузился:

```bash
dmesg | grep DHT
# Ожидаемый вывод:
# [DHT]: DHT Driver © 2026, Chapvic (v2.7)
# [DHT]: driver loaded - /proc/sensors/dht/ (max 32 sensors)
```

### 5. Регистрация датчика

```bash
echo 4 | sudo tee /proc/sensors/dht/export
```

Драйвер автоматически выполнит первое измерение и определит тип датчика.

### 6. Чтение данных

```bash
cat /proc/sensors/dht/gpio4/value
# Вывод:
# H=45.2
# T=23.1
```

### 7. Включение автоопроса

Глобальный автоопрос (один интервал для всех датчиков):

```bash
echo 5 | sudo tee /proc/sensors/dht/auto_interval
```

Индивидуальный интервал для конкретного датчика:

```bash
echo 10 | sudo tee /proc/sensors/dht/gpio4/interval
```

### 8. Выгрузка модуля

```bash
sudo rmmod dht
```

### 9. Использование файла конфигурации (опционально)

Создайте файл `/etc/default/dht`:

```bash
sudo tee /etc/default/dht << 'EOF'
DEBUG=1
AUTO_INTERVAL=10
SENSOR=4
SENSOR=17,5
EOF
```

При следующем `modprobe dht` датчики и интервалы будут настроены автоматически.

## Файл конфигурации

Драйвер при загрузке читает опциональный файл `/etc/default/dht`. Если файл отсутствует, драйвер загружается с настройками по умолчанию.

### Формат

- Строки, начинающиеся с `#`, игнорируются (комментарии)
- Пустые строки игнорируются
- Опции обрабатываются сверху вниз — порядок имеет значение
- Неизвестные опции и неверные значения выводят предупреждение в dmesg

### Глобальные опции

| Опция | Описание | Значение по умолчанию |
|-------|----------|-----------------------|
| `DEBUG` | Включить отладку при загрузке (эквивалент `DEBUG=1`) | 0 |
| `DEBUG=0\|1` | Явно выключить/включить отладку | 0 |
| `AUTO_INTERVAL=n` | Глобальный интервал автоопроса в секундах (2–60). Запускает опрос для всех зарегистрированных датчиков | -1 (выключено) |

### Регистрация датчиков

| Опция | Описание |
|-------|----------|
| `SENSOR=<pin>` | Зарегистрировать датчик на указанном BCM-пине без автоопроса |
| `SENSOR=<pin>,<n>` | Зарегистрировать с индивидуальным интервалом опроса (2–60 секунд; -1 — без опроса) |

### Пример

```bash
# /etc/default/dht
DEBUG=1
AUTO_INTERVAL=10
SENSOR=4             # DHT22 на GPIO4, использует глобальный интервал
SENSOR=17,5          # DHT11 на GPIO17, опрос каждые 5 секунд
SENSOR=22            # Датчик на GPIO22, без автоопроса
```

### Обработка ошибок

| Ситуация | Поведение |
|----------|----------|
| Файл отсутствует | Тихо, отладочное сообщение в dmesg |
| Неизвестная опция | `config: unknown option 'XXX'` в dmesg |
| Неверный пин | `config: SENSOR pin 'XX' invalid (0-27)` в dmesg |
| Неверный интервал | `config: SENSOR interval 'XX' invalid (2-60 or -1)` в dmesg |
| Неверное значение DEBUG | `config: DEBUG='XX' invalid (expected 0 or 1)` в dmesg |
| Неверное значение AUTO_INTERVAL | `config: AUTO_INTERVAL='XX' is not a valid integer` или `out of range` в dmesg |

### Порядок обработки опций

Опции обрабатываются сверху вниз:

- Если `AUTO_INTERVAL=5` стоит **до** `SENSOR=4` — датчик при регистрации автоматически получит глобальный автоопрос
- Если `AUTO_INTERVAL=5` стоит **после** `SENSOR=4` — датчик сначала регистрируется без опроса, затем `AUTO_INTERVAL` запускает polling для всех уже зарегистрированных датчиков

Оба сценария работают корректно.

## Интерфейс procfs

### Глобальные записи

```
/proc/sensors/dht/
├── debug          (rw) — отладка: 0 = выключено (по умолчанию), 1 = включено
├── version        (r)  — версия драйвера
├── export          (w) — записать BCM-номер пина для регистрации датчика
├── unexport        (w) — записать BCM-номер пина для удаления датчика
└── auto_interval  (rw) — глобальный интервал автоопроса (2–60, -1 = выключено)
```

### Записи конкретного датчика

```
/proc/sensors/dht/gpio<pin>/
├── pin            (r)  — BCM-номер GPIO-пина
├── interval       (rw) — интервал автоопроса в секундах (2–60, -1 = выключено)
├── measure         (w) — записать "1" для запуска измерения
│                        (игнорируется, если interval != -1 или активен глобальный автоопрос)
├── status_code    (r)  — код ошибки (0 = успех)
├── status_text    (r)  — описание ошибки
├── value          (r)  — "H=<влажность>\nT=<температура>\n"
├── info           (r)  — тип датчика + время регистрации
└── timestamp      (r)  — Unix-метка времени последнего измерения
```

### Приоритеты опроса

Когда активировано несколько режимов опроса, приоритет следующий:

| Приоритет | Источник | Описание |
|-----------|----------|----------|
| 1 | Глобальный автоопрос | Если `global_auto_interval != -1`, все датчики опрашиваются с этим интервалом, индивидуальные интервалы игнорируются |
| 2 | Индивидуальный интервал | Если глобальный опрос выключен, каждый датчик использует свой `interval` |
| 3 | Ручной режим | Если `interval == -1` и глобальный опрос выключен, измерение запускается записью в `measure` |

## Примеры использования

### Ручной режим

```bash
# Регистрация
echo 4 | sudo tee /proc/sensors/dht/export

# Измерение
echo 1 | sudo tee /proc/sensors/dht/gpio4/measure

# Чтение результата
cat /proc/sensors/dht/gpio4/value
# H=45.2
# T=23.1
```

### Индивидуальный автоопрос

```bash
# Регистрация с интервалом 5 секунд
echo 4 | sudo tee /proc/sensors/dht/export
echo 5 | sudo tee /proc/sensors/dht/gpio4/interval

# Данные обновляются автоматически каждые 5 секунд
cat /proc/sensors/dht/gpio4/value
```

### Глобальный автоопрос

```bash
# Регистрация нескольких датчиков
echo 4  | sudo tee /proc/sensors/dht/export
echo 17 | sudo tee /proc/sensors/dht/export
echo 22 | sudo tee /proc/sensors/dht/export

# Включение глобального опроса (интервал 10 секунд)
echo 10 | sudo tee /proc/sensors/dht/auto_interval

# Все датчики опрашиваются каждые 10 секунд
cat /proc/sensors/dht/gpio4/value
cat /proc/sensors/dht/gpio17/value
cat /proc/sensors/dht/gpio22/value
```

### Чтение в shell-скрипте

```bash
#!/bin/bash
# Мониторинг датчика на GPIO4

SENSOR_DIR="/proc/sensors/dht/gpio4"

while true; do
    echo "--- $(date) ---"
    echo "Влажность: $(grep '^H=' "$SENSOR_DIR/value" | cut -d= -f2)%"
    echo "Температура: $(grep '^T=' "$SENSOR_DIR/value" | cut -d= -f2)°C"
    echo "Статус: $(cat "$SENSOR_DIR/status_text")"
    echo
    sleep 5
done
```

### Чтение в Python

```python
#!/usr/bin/env python3
# Чтение данных с DHT-датчика через procfs

import time

def read_sensor(pin):
    base = f"/proc/sensors/dht/gpio{pin}"
    with open(f"{base}/value") as f:
        data = f.read()
    h = float(data.split("H=")[1].split("\n")[0])
    t = float(data.split("T=")[1].split("\n")[0])
    return h, t

humidity, temperature = read_sensor(4)
print(f"Влажность: {humidity:.1f}%  Температура: {temperature:.1f}°C")
```

```bash
# Создание конфигурации
sudo tee /etc/default/dht << 'EOF'

AUTO_INTERVAL=10
```

### Безопасная выгрузка

```bash

# Полная выгрузка модуля
sudo rmmod dht
```

Драйвер безопасно останавливает все потоки опроса и освобождает ресурсы. Если procfs-файлы открыты, `rmmod` дождётся их закрытия (благодаря счётчику ссылок модуля).

## Архитектура

### Определение GPIO-чипа

Драйвер использует трёхстадийную стратегию для сопоставления BCM-номера пина с GPIO-дескриптором:

1. **Быстрый путь** — если `cached_chip_base` уже известен (после первой успешной регистрации), вычисляется `global = base + bcm_pin`. Это основной случай для всех последующих регистраций.

2. **Прямой поиск** — `gpio_to_desc(bcm_pin)` работает на Pi 3/4, где база GPIO = 0 и BCM-номер совпадает с глобальным номером.

3. **Полное сканирование** — перебор всех GPIO-номеров 0–2048 для поиска чипа Raspberry Pi, у которого локальное смещение совпадает с запрошенным BCM-пином. Необходимо на Pi 5, где база GPIO велика (≥ 512).

При первом успешном поиске база чипа кэшируется, и все последующие регистрации используют быстрый путь.

### Ограничение частоты (Rate Limiting)

Ограничение `MEAS_MIN_GAP` (2 секунды) применяется ко всем измерениям:

- **Ручные измерения** — возвращают `ERR_TOO_SOON`, если прошло менее 2 секунд с последней попытки
- **Автоматический опрос** — тихо пропускает измерение, сохраняя последние данные

DHT-датчики требуют минимум 2 секунды между чтениями — это аппаратное ограничение.

### Безопасная выгрузка

Выгрузка модуля выполняется в две фазы:

**Фаза 1 — Блокировка новых обращений:**
1. Устанавливается флаг `dht_exiting` — новые вызовы `dht_proc_open` возвращают `-ENODEV`
2. Глобальный автоопрос выключается — предотвращает запуск новых потоков
3. Все procfs-записи удаляются — `proc_remove` блокирует выполнение до закрытия всех открытых файлов

**Фаза 2 — Остановка потоков и освобождение памяти:**
4. Список датчиков переносится в локальный список (под блокировкой)
5. Для каждого датчика: остановка потока опроса, уничтожение мьютекса, освобождение памяти

Ключевой момент: после Фазы 1 новые файловые операции невозможны. Счётчик ссылок модуля (увеличиваемый в `dht_proc_open`) не позволяет `rmmod` продолжить выполнение, пока все открытые файлы не закрыты.

### Совместное использование `/proc/sensors`

Драйвер создаёт `/proc/sensors/dht/` внутри общей директории `/proc/sensors/`:

- Если `/proc/sensors` уже существует (создан другим драйвером), драйвер переиспользует его
- Если `/proc/sensors` не существует, драйвер создаёт его
- При выгрузке драйвер удаляет `/proc/sensors` только если он был создан им и оказался пустым (проверка через VFS `iterate_dir`)

### Протокол DHT

Драйвер реализует однопроводной протокол DHT:

1. **Стартовый сигнал** — линия данных подтягивается к нулю на 20 мс
2. **Освобождение линии** — переключение в режим входа, подтягивающий резистор поднимает линию
3. **Чтение 40 бит** — измерение длительности импульсов с наносекундной точностью:
   - ~26 мкс = бит `0`
   - ~70 мкс = бит `1`
   - Порог различения: 40 мкс (`BIT_THRESHOLD`)
4. **Контрольная сумма** — пятый байт равен сумме первых четырёх (mod 256)
5. **Определение типа** — DHT11 передаёт целые числа (байт 1 и 3 = 0), DHT22 — десятичные (16-битные значения с масштабом x10)

### Поток опроса

Каждый датчик с активным автоопросом имеет собственный поток ядра `dht_poll_<pin>`:

- Поток вызывает `dht_do_measurement()` с заданным интервалом
- При активном глобальном интервале он имеет приоритет над индивидуальным
- Поток спит с шагом в 1 секунду для быстрого реагирования на `kthread_should_stop()`
- При удалении датчика или выгрузке модуля поток корректно останавливается

### Загрузка конфигурации

Функция `dht_load_config()` вызывается в конце `dht_driver_init()`, после создания procfs:

1. Открывает `/etc/default/dht` через VFS (`filp_open` + `kernel_read`)
2. Буфер выделяется через `kmalloc` (4096 байт) — нет проблем со стеком
3. Если файл отсутствует — тихо, отладочное сообщение
4. Парсинг построчно: поддержка `#` комментариев, пустых строк, `\r\n`
5. Каждая строка передаётся в `dht_parse_config_line()`, которая вызывает `dht_do_register()` для `SENSOR` или `dht_config_set_auto_interval()` для `AUTO_INTERVAL`

Порядок важен: `AUTO_INTERVAL` до `SENSOR` запускает опрос при регистрации; `AUTO_INTERVAL` после `SENSOR` запускает опрос для уже зарегистрированных датчиков.

## Известные ограничения

1. **Максимум 32 датчика** — ограничение `MAX_SENSORS`, задаётся константой при компиляции
2. **Минимум 2 секунды между измерениями** — аппаратное ограничение DHT-датчиков
3. **Точность измерений зависит от планировщика** — драйвер использует `ktime_get_ns()` для точного измерения импульсов, но в условиях высокой нагрузки возможны ошибки чтения
4. **Нет поддержки прерываний** — опрос выполняется программно (bit-banging), что требует ~20 мс на каждое чтение
5. **Pi 5 требует полного сканирования при первой регистрации** — последующие регистрации используют кэш
6. **Файл конфигурации читается один раз при загрузке** — изменения в `/etc/default/dht` требуют перезагрузки модуля

## Устранение неполадок

### Датчик не регистрируется (ошибка GPIO)

```
[dht_gpio_4]: GPIO descriptor not found
```

**Решение:** Проверьте, что BCM-номер пина правильный. Убедитесь, что пин не занят другим драйвером (например, `w1-gpio`). Проверьте, что датчик подключён к правильному пину.

### Ошибка чтения (контрольная сумма)

```
[dht_gpio_4]: read failed after 3 attempts
```

**Решение:** DHT-датчики чувствительны к таймингу. Убедитесь, что подтягивающий резистор 4.7–10 кОм установлен. Проверьте длину и качество проводов. Включите отладку для диагностики: `echo 1 | sudo tee /proc/sensors/dht/debug`.

### Ручное измерение отклонено

```
status_code: 5
status_text: Too soon since last measurement (min 2s)
```

**Решение:** Драйвер ограничивает частоту измерений. Подождите минимум 2 секунды между ручными измерениями или включите автоопрос.

### Модуль не выгружается

```
rmmod: ERROR: Module dht is in use
```

**Решение:** Закройте все процессы, читающие procfs-файлы (например, скрипты мониторинга). Используйте `lsof | grep /proc/sensors/dht` для поиска открытых файлов.

### Конфигурация не применяется

```
dmesg не показывает сообщений config:
```

**Решение:** Проверьте, что файл `/etc/default/dht` существует и доступен для чтения. Включите отладку для диагностики. Убедитесь, что нет опечаток в именах опций.
