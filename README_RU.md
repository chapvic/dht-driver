# DHT11/DHT22/AM2302 — Драйвер датчиков температуры и влажности

## Обзор

Драйвер ядра Linux для чтения температуры и влажности с датчиков DHT11, DHT22 и AM2302, подключённых к GPIO-пинам Raspberry Pi. Драйвер создаёт интерфейс в procfs по пути `/proc/sensors/dht/` для регистрации датчиков, настройки параметров опроса и получения данных.

**Версия:** 2.6
**Автор:** Chapvic (c) 2026
**Лицензия:** GPL v3

### Ключевые возможности

- Динамическая регистрация датчиков через procfs (export/unexport)
- Индивидуальные записи procfs для каждого датчика: температура, влажность, статус, конфигурация
- Фоновый поток опроса с настраиваемым интервалом для каждого датчика
- Глобальный режим автоопроса с общим интервалом для всех датчиков
- Кэширование базы GPIO-чипа для быстрой регистрации нескольких датчиков на Pi 3/4/5
- Наносекундная точность измерения импульсов для надёжного чтения на всех моделях Pi
- Ограничение частоты измерений (rate limiting) — минимальный интервал 2 секунды
- Безопасная выгрузка модуля со счётчиком ссылок
- Совместное использование `/proc/sensors` — сосуществование с другими драйверами датчиков

## Поддерживаемое оборудование

### Датчики

| Датчик | Влажность | Температура | Разрешение | Особенности |
|--------|----------|-------------|------------|-------------|
| DHT11 | 20–90% | 0–50 °C | Целые числа | Базовая модель, низкая цена |
| DHT22 (AM2302) | 0–100% | −40–80 °C | Десятичные доли | Высокая точность, отрицательные температуры |
| AM2302 | 0–100% | −40–80 °C | Десятичные доли | DHT22 в корпусе с резистором |

Тип датчика определяется автоматически по формату данных после первого успешного измерения — ручная настройка не требуется.

## Подключение

### Схема

```
DHT11/DHT22/AM2302          Raspberry Pi
+-------------+
| VCC  -------+----------- 3.3V (Pin 1)
| DATA -------+----------- GPIO (BCM pin, например GPIO23)
|  |          |
|  +-[10kOm]-+----------- 3.3V (подтягивающий резистор)
| GND  -------+----------- GND (Pin 6)
+-------------+
```

### Важные замечания

- **Напряжение:** датчики питаются от 3.3 В, не от 5 В
- **Подтягивающий резистор:** 10 кОм между DATA и VCC. AM2302 имеет встроенный резистор, для DHT11/DHT22 — внешний
- **BCM-нумерация:** драйвер использует нумерацию BCM (Broadcom), а не физические пины. Допустимые номера: 0–27
- **Длина провода:** до 20 м для DHT22, до 1 м для DHT11

## Интерфейс procfs

### Глобальные записи

```
/proc/sensors/dht/
+-- debug          (rw)  — отладочный вывод: 0 = выкл (по умолчанию), 1 = вкл
+-- version        (r)   — версия драйвера
+-- export         (w)   — запись номера BCM-пина для регистрации датчика
+-- unexport       (w)   — запись номера BCM-пина для удаления датчика
+-- auto_interval  (rw)  — глобальный интервал автоопроса (2-60, -1 = выкл)
```

### Записи конкретного датчика

```
/proc/sensors/dht/gpio<pin>/
+-- pin           (r)   — номер BCM-пина GPIO
+-- interval      (rw)  — интервал автоопроса в секундах (2-60, -1 = выкл)
+-- measure       (w)   — запись "1" для запуска измерения
|                          (игнорируется, если interval != -1 или активен глобальный автоопрос)
+-- status_code   (r)   — код ошибки (0 = успех)
+-- status_text   (r)   — описание ошибки
+-- value         (r)   — "H=<влажность>\nT=<температура>\n"
+-- info          (r)   — тип датчика + время регистрации
+-- timestamp     (r)   — Unix-метка времени последнего измерения
```

### Приоритеты опроса

| Источник | Приоритет | Поведение |
|----------|-----------|-----------|
| Глобальный автоопрос (`auto_interval != -1`) | Высший | Опрашивает все датчики с общим интервалом. Индивидуальные интервалы игнорируются. Ручные измерения запрещены. |
| Индивидуальный интервал (`interval != -1`) | Средний | Опрашивает конкретный датчик с заданным интервалом. Ручные измерения запрещены. |
| Ручное измерение (`measure`) | Низший | Однократное измерение по запросу. Доступно только если все автоопросы выключены. |

## Примеры использования

### Ручной режим

```bash
# Регистрация
echo 23 | sudo tee /proc/sensors/dht/export

# Измерение
echo 1 | sudo tee /proc/sensors/dht/gpio23/measure

# Чтение
cat /proc/sensors/dht/gpio23/value
# H=45.2
# T=23.1

# Проверка статуса
cat /proc/sensors/dht/gpio23/status_text
# SUCCESS

cat /proc/sensors/dht/gpio23/status_code
# 0

# Метка времени последнего измерения
cat /proc/sensors/dht/gpio23/timestamp
# 1791234567
```

### Индивидуальный автоопрос для конкретного датчика

```bash
# Регистрация двух датчиков
echo 4  | sudo tee /proc/sensors/dht/export
echo 23 | sudo tee /proc/sensors/dht/export

# Разные интервалы для каждого
echo 5  | sudo tee /proc/sensors/dht/gpio4/interval    # каждые 5 секунд
echo 15 | sudo tee /proc/sensors/dht/gpio23/interval   # каждые 15 секунд

# Чтение в любой момент
cat /proc/sensors/dht/gpio4/value
cat /proc/sensors/dht/gpio23/value

# Остановка опроса конкретного датчика
echo -1 | sudo tee /proc/sensors/dht/gpio4/interval
```

### Глобальный автоопрос

```bash
# Регистрация датчиков
echo 4  | sudo tee /proc/sensors/dht/export
echo 23 | sudo tee /proc/sensors/dht/export

# Включение общего опроса каждые 10 секунд
echo 10 | sudo tee /proc/sensors/dht/auto_interval

# Теперь оба датчика опрашиваются автоматически
# Ручные измерения недоступны:
echo 1 | sudo tee /proc/sensors/dht/gpio23/measure
# (запись игнорируется)

# Выключение глобального автоопроса
echo -1 | sudo tee /proc/sensors/dht/auto_interval
```

### Использование в shell-скрипте

```bash
#!/bin/bash
# monitor.sh — мониторинг температуры и влажности

PIN=23
INTERVAL=10

echo "$PIN" | sudo tee /proc/sensors/dht/export
echo "$INTERVAL" | sudo tee /proc/sensors/dht/gpio$PIN/interval

while true; do
    TIMESTAMP=$(cat /proc/sensors/dht/gpio$PIN/timestamp)
    VALUE=$(cat /proc/sensors/dht/gpio$PIN/value)
    STATUS=$(cat /proc/sensors/dht/gpio$PIN/status_text)
    
    HUMIDITY=$(echo "$VALUE" | grep '^H=' | cut -d= -f2)
    TEMP=$(echo "$VALUE" | grep '^T=' | cut -d= -f2)
    
    echo "[$(date -d @$TIMESTAMP '+%Y-%m-%d %H:%M:%S')] T=${TEMP}C  H=${HUMIDITY}%  [$STATUS]"
    sleep "$INTERVAL"
done
```

### Использование в Python

```python
#!/usr/bin/env python3
import time

PROC_BASE = "/proc/sensors/dht"

def register_sensor(pin):
    with open(f"{PROC_BASE}/export", "w") as f:
        f.write(str(pin))

def read_sensor(pin):
    with open(f"{PROC_BASE}/gpio{pin}/value") as f:
        data = f.read()
    result = {}
    for line in data.strip().split("\n"):
        key, val = line.split("=")
        result[key] = float(val)
    return result

def get_status(pin):
    with open(f"{PROC_BASE}/gpio{pin}/status_text") as f:
        return f.read().strip()

# Регистрация
register_sensor(23)
time.sleep(3)  # ожидание первого измерения

# Чтение
data = read_sensor(23)
print(f"Температура: {data['T']} C")
print(f"Влажность:   {data['H']} %")
print(f"Статус:      {get_status(23)}")
```

### Безопасная выгрузка

```bash
# Остановка всех потоков опроса
echo -1 | sudo tee /proc/sensors/dht/auto_interval
for dir in /proc/sensors/dht/gpio*/; do
    [ -d "$dir" ] && echo -1 | sudo tee "$dir/interval"
done

# Удаление датчиков
for dir in /proc/sensors/dht/gpio*/; do
    [ -d "$dir" ] && echo "$(basename $dir | sed 's/gpio//')" | sudo tee /proc/sensors/dht/unexport
done

# Выгрузка модуля
sudo rmmod dht
```

> **Примечание:** `rmmod` безопасен даже с открытыми файлами в procfs — счётчик ссылок модуля не позволит выгрузить модуль, пока файлы не закрыты.

## Коды ошибок

### Коды драйвера

| Код | Константа | Описание | Возможные причины |
|-----|-----------|----------|-------------------|
| 0 | `ERR_SUCCESS` | Успех | — |
| 1 | `ERR_PIN_INVALID` | Неверный номер пина | Пин вне диапазона 0–27 |
| 2 | `ERR_GPIO_REQUEST` | Ошибка GPIO | Пин занят другим драйвером, GPIO-чип не найден |
| 3 | `ERR_READ_FAILED` | Ошибка чтения датчика | Плохой контакт, неверная подтяжка, неисправен датчик |
| 4 | `ERR_AUTO_MODE` | Ручное измерение в режиме автоопроса | Выключите автоопрос перед ручным измерением |
| 5 | `ERR_TOO_SOON` | Слишком частое измерение | Минимальный интервал — 2 секунды (rate limiting) |

### Коды errno при экспорте

| errno | Описание | Причина |
|-------|----------|--------|
| `-EINVAL` | Неверный аргумент | Номер пина не является числом или вне диапазона 0–27 |
| `-ENODEV` | Нет такого устройства | Пин не зарегистрирован (при unexport) |
| `-EBUSY` | Занято | Пин уже зарегистрирован (при export) |
| `-ENOMEM` | Не хватает памяти | Не удалось выделить память под структуру датчика |

## Архитектура

### Обнаружение GPIO-чипа

Драйвер использует трёхступенчатую стратегию определения GPIO-дескриптора по BCM-номеру пина:

**Stage 1 — Быстрый путь (кэш):**
Если `cached_chip_base` уже известен (>= 0), глобальный номер вычисляется как `base + bcm_pin`. Это срабатывает после первой успешной регистрации.

**Stage 2 — Прямой поиск:**
`gpio_to_desc(bcm_pin)` — работает на Pi 3/4, где база GPIO-чипа равна 0, и BCM-номер совпадает с глобальным.

**Stage 3 — Полный скан:**
Перебор всех глобальных номеров 0–2048 с поиском чипа Raspberry Pi, где локальное смещение совпадает с BCM-номером. Необходим на Pi 5, где база >= 512.

При первом успешном обнаружении база кэшируется — все последующие регистрации используют Stage 1.

### Rate limiting

Минимальный интервал между измерениями — 2 секунды (`MEAS_MIN_GAP`). Применяется ко всем типам измерений:

- **Ручное измерение:** если интервал слишком короткий, пользователь получает `ERR_TOO_SOON`
- **Автоопрос:** если интервал слишком короткий, измерение тихо пропускается, последние данные сохраняются

### Безопасная выгрузка модуля

Драйвер реализует двухфазную очистку для предотвращения состояний гонки:

**Фаза 1 — Блокировка нового доступа:**
1. Устанавливается флаг `dht_exiting` — новые вызовы `dht_proc_open` возвращают `-ENODEV`
2. Отключается глобальный автоопрос
3. Удаляются все procfs-записи (`proc_remove` блокируется, пока все открытые файлы не закроются)

**Фаза 2 — Остановка потоков и освобождение памяти:**
4. Список датчиков переносится в локальный список (новые датчики не могут появиться — procfs уже удалён)
5. Для каждого датчика: остановка потока опроса, уничтожение мьютекса, освобождение памяти

Счётчик ссылок модуля (`try_module_get` / `module_put` в `dht_proc_open` / `dht_proc_release`) гарантирует, что `rmmod` не завершится, пока открыт хотя бы один файл в procfs.

### Совместное использование /proc/sensors

**Проблема:** драйвер создаёт папку `/proc/sensors` при загрузке и удаляет при выгрузке. Если другой драйвер тоже использует `/proc/sensors`, безусловное удаление уничтожает его записи.

**Решение:** флаг `we_created_parent` отслеживает, кто создал папку:

**При загрузке (`dht_driver_init`):**
- `proc_mkdir("sensors", NULL)` вернул handle — мы создали папку, `we_created_parent = true`, создаём `dht` как дочернюю
- `proc_mkdir("sensors", NULL)` вернул `NULL` — папка уже существует, `we_created_parent = false`, создаём `dht` через полный путь `proc_mkdir("sensors/dht", NULL)` — ядро само найдёт существующий родитель

**При выгрузке (`dht_driver_exit`):**
- `proc_remove(proc_dir)` — удаляем только своё дерево `/proc/sensors/dht/`
- Если `we_created_parent` — проверяем пустоту `/proc/sensors` через VFS (`filp_open` + `iterate_dir`):
  - Пусто — удаляем `/proc/sensors`
  - Есть чужие подпапки — оставляем, пишем в лог: `/proc/sensors not removed (other drivers using it)`
- Если `!we_created_parent` — вообще не трогаем `/proc/sensors`

### Протокол DHT

1. **Старт-сигнал:** драйвер подтягивает линию данных к нулю на 20 мс
2. **Освобождение:** переключение в режим входа, подтягивающий резистор поднимает линию
3. **Ответ датчика:** датчик отвечает после 20–40 мкс
4. **Чтение 40 бит:** каждый бит — низкий импульс (~50 мкс) + высокий импульс
   - ~26 мкс = «0», ~70 мкс = «1»
   - Порог: `BIT_THRESHOLD` = 40 мкс
5. **Контрольная сумма:** 5-й байт = сумма первых 4 байт (mod 256)
6. **Определение типа:** по формату данных (DHT11 — целые числа, DHT22 — десятичные)

### Поток опроса

Каждый датчик с активным интервалом имеет собственный поток ядра (`kthread`):
- Имя потока: `dht_poll_<pin>`
- Цикл: измерение → `msleep(interval * 1000)` → повтор
- Остановка: `kthread_stop()` с ожиданием завершения (до ~400 мс)
- При активном глобальном автоопросе индивидуальные потоки не создаются — используется единый поток `dht_global_poll`

## Известные ограничения

1. **Максимум 32 датчика** — жёсткий лимит `MAX_SENSORS`. Увеличивается пересборкой с другим значением `#define MAX_SENSORS`
2. **Датчики DHT не поддерживают прерывания** — чтение основано на поллинге с занятостью CPU на ~20 мс на каждое измерение
3. **Минимальный интервал 2 секунды** — ограничение самих датчиков DHT, не драйвера
4. **Только Raspberry Pi** — драйвер проверяет метку GPIO-чипа на соответствие известным чипам Pi
5. **BCM-номера 0–27** — расширенные пины (28+) не поддерживаются
6. **Точность ограничена самим датчиком** — DHT11 ±2 °C / ±5%, DHT22 ±0.5 °C / ±2%

## Устранение неполадок

### Датчик не регистрируется

```bash
echo 23 | sudo tee /proc/sensors/dht/export
cat /proc/sensors/dht/gpio23/status_text
# GPIO request/lookup failed
```

**Решение:** Пин занят другим драйвером. Проверьте:
```bash
cat /sys/kernel/debug/gpio | grep 23
# Освободите пин или используйте другой
```

### Чтение всегда завершается ошибкой

```bash
cat /proc/sensors/dht/gpio23/status_text
# Sensor data read failed
```

**Решения:**
- Проверьте подключение (VCC, DATA, GND)
- Убедитесь, что подтягивающий резистор 10 кОм установлен (DHT11/DHT22)
- Увеличьте длину старт-сигнала — драйвер использует 20 мс по умолчанию
- Включите отладку: `echo 1 | sudo tee /proc/sensors/dht/debug` и проверьте `dmesg`
- Проверьте длину провода — для DHT11 не более 1 м

### Ошибка «Too soon»

```bash
echo 1 | sudo tee /proc/sensors/dht/gpio23/measure
cat /proc/sensors/dht/gpio23/status_text
# Too soon since last measurement (min 2s)
```

**Решение:** Подождите минимум 2 секунды между ручными измерениями. Это ограничение самих датчиков DHT.

### rmmod возвращает «Module is in use»

```bash
sudo rmmod dht
# ERROR: Module dht is in use
```

**Решение:** Закройте все открытые файлы в `/proc/sensors/dht/`. Проверьте:
```bash
lsof /proc/sensors/dht/
# Или просто закройте все терминалы, которые читали procfs
```

### /proc/sensors не удаляется при выгрузке

```bash
dmesg | tail -5
# [DHT]: /proc/sensors not removed (other drivers using it)
```

**Это нормально.** Другой драйвер использует `/proc/sensors`. Папка будет удалена, когда последний драйвер выгрузится и папка опустеет.

### Неправильные значения температуры/влажности

- Проверьте, что используется правильный датчик (DHT11 vs DHT22)
- Тип определяется автоматически — посмотрите `cat /proc/sensors/dht/gpio<pin>/info`
- Убедитесь, что напряжение 3.3 В, а не 5 В (при 5 В показания могут быть некорректными)
- Проверьте целостность данных: `cat /proc/sensors/dht/gpio<pin>/status_code` должен быть 0
