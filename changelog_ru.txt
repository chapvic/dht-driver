                    Журнал изменений — модуль ядра DHT

Версия 2.8  (21.09.2026)
────────────────────────────────────────────────────────────────────────────────

  Исправления и повышение надёжности по сравнению с v2.7.

  Критические
  ───────────
  1. Use-after-free при unexport
     Добавлен struct kref refcount в dht_sensor. В dht_proc_open берётся
     ссылка на сенсор (kref_get_unless_zero), в dht_proc_release — отпускается
     (kref_put). Сенсор освобождается только когда последний дескриптор закрыт.
     dht_sensor_release (callback kref) выполняет: stop_poll -> proc_remove ->
     mutex_destroy -> kfree.

  2. TOCTOU при регистрации
     В dht_do_register добавлена повторная проверка дубликата под list_lock
     непосредственно перед list_add. Если два потока одновременно прошли
     первичную проверку, второй получает -EBUSY и освобождает сенсор через
     dht_sensor_put.

  3. Poll thread не останавливается
     В dht_poll_thread_fn добавлен выход из цикла (break) при
     effective_interval == -1 (оба интервала отключены). Ранее поток мог
     вращаться бесконечно, если global_auto_interval был установлен в -1
     после запуска потока.

  Логические
  ──────────
  4. Температура DHT11 ниже 5 °C
     Температура теперь интерпретируется по типу, определённому из влажности:
     если h > 1000 (DHT11), то c = data[2] * 10 выполняется в той же ветке.
     Удалена отдельная эвристика "if (c > 1250)", которая пропускала значения
     0-4 °C для сенсоров DHT11.

  5. Изменение типа сенсора при каждом измерении
     В dht_do_measurement тип записывается только если
     sensor_type == SENSOR_TYPE_UNKNOWN. Первое успешное измерение фиксирует
     тип навсегда, предотвращая ложные смены типа из-за пограничных значений
     влажности.

  Надёжность
  ─────────
  6. Вытеснение в timing-critical секции
     Добавлены preempt_disable() / preempt_enable() вокруг цикла чтения 40 бит
     в dht_read_sensor. Прерывания НЕ отключаются — импульсы DHT (~70 мкс)
     достаточно широкие, и IRQ jitter допустим.

  7. Проверка gpiod_cansleep()
     Если GPIO находится за sleeping-экспандером (например, I2C GPIO-чип),
     чтение немедленно возвращает ERR_GPIO_REQUEST с диагностическим
     сообщением в dmesg вместо молчаливого искажения данных.

  Чистота кода
  ────────────
  8. Удаление мёртвого кода
     Удалены LOG_BUF_LEN (был определён, но не использовался) и поле
     info_text[INFO_BUF_LEN] из struct dht_sensor (256 байт на сенсор,
     не использовалось). INFO_BUF_LEN оставлен — применяется как размер
     локального буфера в sensor_info_read.

  9. kfree -> dht_sensor_put
     В пути ошибки dht_create_sensor_proc в dht_do_register прямой kfree
     заменён на dht_sensor_put, поскольку kref_init уже был вызван до
     ошибки.

  Намеренно не изменено
  ─────────────────────
  - gpiod_to_chip() / gpio_to_desc() устарели, но замена на gpiod_get() через
    device tree требует полной переработки модели регистрации. Оставлено как
    есть с пониманием, что в будущих ядрах потребуется миграция.
  - Права procfs (0666 для debug/auto_interval) — выбор пользователя/
    дистрибутива, не баг.


Версия 2.7  (21.09.2026)
────────────────────────────────────────────────────────────────────────────────

  Поддержка файла конфигурации

  Новая возможность: опциональный файл конфигурации /etc/default/dht,
  считываемый при загрузке модуля. Если файл отсутствует, драйвер
  загружается со значениями по умолчанию.

  Формат:
    - Строки, начинающиеся с '#', и пустые строки игнорируются
    - Неизвестные опции вызывают предупреждение в dmesg
    - Недопустимые значения вызывают предупреждение в dmesg

  Глобальные опции:
    DEBUG              Включить отладку при загрузке (= DEBUG=1)
    DEBUG=0|1          Явно выключить/включить отладку
    AUTO_INTERVAL=n    Глобальный интервал автоопроса в секундах (2-60)

  Регистрация сенсоров:
    SENSOR=<pin>       Зарегистрировать сенсор на BCM-пине (без автоопроса)
    SENSOR=<pin>,<n>   Зарегистрировать с per-sensor интервалом (2-60 сек)

  Реализация:
    - dht_do_register(pin, interval) извлечена из export_write
    - dht_parse_config_line() парсит одну строку за раз
    - dht_load_config() читает /etc/default/dht через VFS
    - Буфер выделяется через kmalloc (без переполнения стека)
    - Вызывается в конце dht_driver_init после создания procfs

  Опции обрабатываются сверху вниз:
    - AUTO_INTERVAL до SENSOR: сенсор получает глобальный интервал при
      регистрации
    - AUTO_INTERVAL после SENSOR: сенсор регистрируется, затем глобальный
      опрос запускается для всех существующих сенсоров


Версия 2.6  (20.09.2026)
────────────────────────────────────────────────────────────────────────────────

  Shared /proc/sensors, безопасная выгрузка, rate limiting, определение GPIO-чипа

  - Shared /proc/sensors: драйвер создаёт /proc/sensors только если его нет;
    удаляет при выгрузке только если сам создал и оно пусто
  - Безопасная выгрузка модуля с двухфазным отключением и счётчиком ссылок
  - Rate limiting для всех измерений (ручные и автоопрос, мин. 2 сек)
  - Определение GPIO-чипа: трёхстадийный поиск (кэш, прямой, полный скан)
    с проверкой метки чипа для совместимости с Pi 3/4/5
  - Наносекундная точность измерения импульсов для надёжного чтения на всех
    моделях Pi


Версия 2.5  (18.09.2026)
────────────────────────────────────────────────────────────────────────────────

  Начальный релиз

  - Динамический export/unexport сенсоров через procfs (/proc/sensors/dht/)
  - Per-sensor записи: pin, interval, measure, status_code, status_text,
    value, info, timestamp
  - Фоновый поток опроса с настраиваемым per-sensor интервалом
  - Глобальный режим автоопроса с общим интервалом
  - Поддержка сенсоров DHT11, DHT22, AM2302
  - Совместимость с Raspberry Pi 3/4/5 (чипы BCM2835, BCM2711, RP1)
