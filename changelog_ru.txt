v2.8.3 (21.09.2026) — Критические исправления
---------------------------------------------

Критические исправления:
  #9  Use-after-free в dht_driver_exit при удалении procfs
      Phase 1 (proc_remove(proc_dir)) удаляет все подкаталоги gpio<pin>/,
      освобождая proc_dir_entry каждого сенсора. Phase 2 вызывает
      dht_sensor_put → dht_sensor_release → proc_remove(sensor->proc_dir),
      обращаясь к уже освобождённой памяти. С SLUB это проходит незаметно,
      но KASAN/CONFIG_DEBUG_SLAB ловит ошибку.
      Фикс: sensor->proc_dir = NULL перед dht_sensor_put в Phase 2.

  #10 Неправильный расчёт отрицательной температуры для DHT22
      Код c = -c не маскирует бит знака (бит 15). Для DHT22
      c = (data[2] << 8) | data[3]. При установленном бите знака
      c содержит 0x8000 | (abs_temp * 10). c = -c даёт
      -(32768 + abs_temp * 10) вместо -(abs_temp * 10).
      Пример: T=-25.1°C → data[2]=0x80, data[3]=0xFB → c=33019
      → c=-33019 → вывод "T=-3301.9" вместо "T=-25.1".
      Фикс: c = -(c & 0x7FFF) — маскирование бита знака перед отрицанием.
      Для DHT11 не влияет (data[2] в диапазоне 0-50, бит 7 не установлен).

Средние исправления:
  #11 dht_read_sensor использует sensor->gpiod вместо повторного resolve
      Функция принимала int pin и вызывала dht_find_desc(pin) заново,
      хотя сенсор уже имеет валидный дескриптор в sensor->gpiod.
      Избыточно и потенциально небезопасно при изменении GPIO-подсистемы.
      Фикс: изменена сигнатура на dht_read_sensor(int pin, struct gpio_desc *desc, ...)
      Дескриптор передаётся из dht_do_measurement через sensor->gpiod.

Низкие исправления:
  #12 Неправильный формат отрицательной температуры в debug-логе
      pin_dbg(..., "T=%d.%d", temp / 10, temp % 10) для temp = -251
      выводил "T=-25.-1" вместо "T=-25.1".
      Фикс: добавлена ветка if (temp < 0) с форматом "T=-%d.%d"
      через (-temp) / 10 и (-temp) % 10.


v2.8.2 (21.09.2026) — Исправления средней и высокой критичности
-----------------------------------------------------------------

Высокая критичность:
  #5  dht_start_poll/dht_stop_poll вызывались без list_lock в sensor_interval_write
      Гонка: два параллельных вызывающих могли оба создать poll thread
      (утечка task_struct, zombie-поток) или оба остановить его
      (use-after-free на уже освобождённом task_struct).
      Фикс: обёрнуты в mutex_lock(&list_lock) / mutex_unlock(&list_lock).

  #6  Параллельное bit-bang чтение на одном GPIO
      Ручное измерение и auto-poll могли одновременно читать один GPIO.
      Два одновременных bit-bang на одной линии гарантированно портили данные.
      Фикс: добавлен atomic_t measuring в struct dht_sensor.
      atomic_cmpxchg(&sensor->measuring, 0, 1) перед GPIO-чтением.
      Для ручных — ERR_READ_FAILED "Measurement already in progress".
      Для авто — молча пропускается, предыдущие данные сохраняются.

Средняя критичность:
  #7  auto_interval_write молча отключался при невалидном значении
      Значения вне диапазона [2, 60] (кроме -1) молча устанавливали
      global_auto_interval = -1 и возвращали успех.
      Фикс: return -EINVAL для значений вне [MIN_INTERVAL, MAX_INTERVAL],
      кроме -1 (явное отключение). Поведение теперь согласовано с
      sensor_interval_write.

  #8  Эвристика DHT11/DHT22 не работала при низкой влажности
      Порог h > 1000 ложно определял DHT11 с влажностью <= 3%
      (h = data[0]*256 < 1000) как DHT22. Значения выводились
      без масштабирования * 10.
      Фикс: добавлена вторичная проверка — если h <= 1000, но
      data[1] == 0 && data[3] == 0 (дробные байты нулевые, как у DHT11)
      и data[0] <= 100 && data[2] <= 50 (в диапазоне DHT11),
      классифицируется как DHT11 с масштабированием * 10.


v2.8.1 (21.09.2026) — Исправление poll thread
---------------------------------------------

  #4  Poll thread выходил без очистки poll_thread при отключении интервалов
      Когда effective_interval == -1, поток делал break, но
      sensor->poll_thread оставался указывать на завершённый поток.
      Повторное включение auto_interval не запускало новый поток
      (dht_start_poll видел non-NULL).
      Фикс: вместо break реализован idle-цикл — поток спит по 1 секунде,
      проверяя kthread_should_stop(). Если интервалы снова включаются,
      поток возобновляет опрос. poll_thread остаётся валидным всё время.


v2.8 (21.09.2026) — Базовый релиз с критическими исправлениями
---------------------------------------------------------------

Критические исправления:
  #1  kref refcounting — use-after-free при unexport с открытым fd
      Сенсор удалялся из списка и освобождался, но procfs-файл
      всё ещё держал указатель. Чтение из /proc после unexport
      приводило к use-after-free.
      Фикс: struct kref refcount в dht_sensor.
      dht_proc_open вызывает kref_get, dht_proc_release — kref_put.
      Сенсор жив до закрытия всех procfs-файлов.

  #2  TOCTOU при регистрации сенсора
      Проверка дубликата и list_add не были атомарны — два параллельных
      export одного пина могли оба пройти проверку и оба добавить сенсор.
      Фикс: повторная проверка дубликата под list_lock перед list_add.

  #3  Выход poll thread при отключении интервалов
      Поток делал break и освобождался, но poll_thread не очищался.
      (Исправлено в v2.8.1 через idle-цикл.)

Логические исправления:
  #1a Температура DHT11 ниже 5°C неправильно интерпретировалась
      c <= 1250 без конвертации * 10 — DHT11 показывал температуру
      с десятичной точкой вместо целого значения.
      Фикс: проверка типа сенсора по влажности (h > 1000 для DHT11),
      затем единая обработка температуры.

  #1b Фиксация типа сенсора после первого измерения
      sensor_type == SENSOR_TYPE_UNKNOWN при первом чтении,
      затем тип блокируется. Предотвращает ложные переключения
      типа из-за граничных значений влажности.

Надёжность:
  #1c preempt_disable / preempt_enable вокруг bit-bang цикла
      Bit-bang timing критичен — вытеснение во время цикла чтения
      приводило к искажению данных. preempt_disable предотвращает
      вытеснение, preempt_enable восстанавливает после цикла.

  #1d gpiod_cansleep() проверка перед чтением
      GPIO за I2C-экспандерами (sleeping GPIO) не работают с
      non-sleeping gpiod_get_value в tight loop.
      Фикс: gpiod_cansleep(desc) — возвращает ERR_GPIO_REQUEST
      с сообщением "GPIO is on a sleeping chip".

Очистка кода:
  #1e Удаление мёртвого кода (LOG_BUF_LEN, info_text)
  #1f kfree заменён на dht_sensor_put в путях ошибки
      Использование kref API для корректного освобождения.

Намеренно не изменено:
  - Deprecated GPIO API (gpio_to_desc / desc_to_gpio)
    Миграция на gpiod_get через device tree требует мажорной версии.
  - Права procfs (0644 / 0444)
    Текущие права обеспечивают доступ из userspace.


v2.7 (21.09.2026) — Файл конфигурации
--------------------------------------

  - Добавлена поддержка файла конфигурации /etc/default/dht
  - Чтение при загрузке модуля, регистрация сенсоров автоматически
  - Опции: DEBUG, DEBUG=0|1, AUTO_INTERVAL=n, SENSOR=<pin>, SENSOR=<pin>,<n>
  - Строки с '#' и пустые строки игнорируются
  - Неизвестные опции и невалидные значения — предупреждения в dmesg


v2.6 (20.09.2026) — Shared procfs, safe unload, rate limiting
---------------------------------------------------------------

  - Shared /proc/sensors: сосуществование с другими драйверами сенсоров
  - Двухфазный cleanup в dht_driver_exit:
    Phase 1: блокировка новых доступов, удаление procfs
    Phase 2: остановка потоков, освобождение памяти
  - Module reference counting через dht_proc_open / dht_proc_release
  - Rate limiting: MEAS_MIN_GAP (2 секунды) для всех измерений
  - Флаг dht_exiting для отклонения новых open при выгрузке


v2.5 (18.09.2026) — Начальный релиз
-------------------------------------

  - Драйвер DHT11/DHT22/AM2302 для Raspberry Pi
  - Procfs интерфейс /proc/sensors/dht/
  - Динамическая регистрация через export/unexport
  - Per-sensor proc-записи: pin, interval, measure, status_code,
    status_text, value, info, timestamp
  - Background polling с настраиваемым интервалом
  - Global auto-poll режим
  - GPIO chip base caching для Pi 3/4/5
  - Nanosecond-precision pulse timing
  - Поддержка ядер 4.x — 6.x (struct proc_ops / file_operations,
    pde_data / PDE_DATA)

Совместимость
